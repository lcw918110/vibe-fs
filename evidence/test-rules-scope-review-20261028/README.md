## 第 010 条：合同与测试实现的边界

现在限定为：未经正式规范修订，不得放宽“现行正式合同已确定的验收判据”、缩小该合同要求的范围，或把按该判据应阻塞验收的问题降为不影响通过。

推导如下：

1. 正式合同规定必须成立的承诺；某份测试只是检验这些承诺的一种实现。现存断言、历史阈值或临时检查不因已经写入测试就自动成为正式合同。
2. 同一合同可能有多种充分的测试方式。替换夹具、补充回归、删除重复断言，只要保留现行合同的有效保护，就没有改变承诺，不必为此先改规范。
3. 局部验证减少的是本次取得证据的范围，不是正式验收义务。必须据实报告实际范围，不能将其结果写成完整验收通过。
4. 反过来，删除仍在保护现行承诺的断言、减少合同要求的场景、把合同规定的阻塞失败写成警告，仍违反本条。不能借“测试重构”或“聚焦运行”绕过它。
5. 发布验收仍不能挑选偶然通过的重跑结果掩盖问题。其他验证也受 021 的如实报告要求约束；恢复原来的发布语境不授予隐藏失败的空间。

等覆盖性能对照是另一项约束：减少属性样本、改变 seed、丢失失败缩减能力、增加跳过或压低原有预算，都不能直接算作同等验证变快。010 的合同限定没有取消这一段。

## 边界推导与反例

### 资源隔离不等于所有场景互不交互

并发冲突或同一生命周期的测试，本来就需要多个参与者共享资源。若要求每个用例的所有资源一律独立，会直接排除 002、014 要求的场景。正确边界在所有权：共享夹具承担其作用域内的准备与清理，场景之外不能遗留污染。共用只读准备可以成立；共用未重置的可变状态、导致另一用例结果依赖执行顺序，仍应被拒绝。

这也解释了 008 的双向证据为什么要带条件。关闭单一临时目录的回归没有必要另造一项长期后台工作；已有调用与挂起恢复回归同时涉及结束和在途保护，就必须两者都证明。清理可以依合同取消本次拥有的工作，不能误杀合同要求继续履行的工作。

### 性能结论的范围决定比较范围

声称“整套测试更快”，至少需要同等覆盖的完整入口对照，并计入准备、排空和回收。仅修改共享运行器的一条诊断信息，则不能仅凭文件位于全局入口就推导出完整性能基准的义务；应根据其实际影响验证错误报告和退出行为。如果改动影响调度、计数或资源回收，验证范围可能仍须扩大，但依据是这些影响及受托目标，不是一个无条件的文件类别。

这次任务是规则范围修订，没有新的性能实现或收益声明，因此重跑规范套件；没有用这一轮规范测试时间更新此前完整 unit 的性能结论。

### 参数化时间与固定边界分别处理

合同若将超时预算定义为输入，测试较小预算可以覆盖相同的逻辑关系。合同若要求某工作跨过固定物理期限仍受保护，缩短实际等待就可能避开原故障。已有 repository-programming 006 的 10.5 秒回归针对旧 10 秒边界，其时长不能因为 L4 的澄清而缩小。本轮没有修改任何预算、测试时长或回归断言。

参数化单项验证合理，也不自动证明性能前后等覆盖。若优化对照改变了原有预算，仍须服从 010，不能直接把差值计为提效。

### 无命中、空集合与漏扫不能混为一谈

检查器扫描了所有必需文件且未发现违规，是合法通过；必需目录不存在导致根本没有扫描，是检查失败。可选目标集合能否为空由其现行合同决定。009 的限定只避免通用规则替具体合同决定这一点；当前要求非空的聚焦套件不会因此变成允许空跑。

### 复用与形式检查都要回到实际需要

“避免无收益的复杂度”不能推出“通用夹具或缓存一律禁止”。多个场景共享昂贵且不可变的准备，可能减少等待与维护成本；缓存失效、清理和复杂度也必须计入。没有当前需要或可说明收益的框架仍无引入依据。

同样，“语义充分性不能由关键词证明”不意味着静态约束不可检查。文件归属、指定禁令等可以有精确检查；业务行为是否成立不能用源码中出现某个词替代。对具体静态门禁，仍要证明正常情况可过、目标违约会失败。

### 控制变量不等于永远固定环境

比较并发策略时，并发度就是声明的目标变量；若把所有环境变化都排除，便不能开展这项实验。可比性要求其余条件可比、用例身份及覆盖不变、完整成本被计入。缺少工具、崩溃或漏执行仍是无效收益来源，不能仅靠声明它们是“目标改动”而变成提速证据。
