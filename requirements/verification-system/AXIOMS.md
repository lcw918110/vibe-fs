# 测试与验证规则

本文约束本仓怎样写测试、跑测试、报告结果。它是 `verification-system` 的唯一规则正文：`WHAT.md` 只作导航，检查器按本文读取条款。

## 规则

1. **测试要能红。** 被测行为违约时必须失败。为通过而放宽断言，等于没写。
2. **一次只验这次改了什么。** 选足以暴露目标违约的最小边界：纯计算直接断言，逻辑时序用虚拟时间，真实进程与文件用真实组合。互不依赖的场景分开跑。
3. **判定依据不照抄实现。** 断言对照行为与公开契约，不对照内部结构、生成符号或私有字段。
4. **静态门禁可红可绿。** 每个门禁要有合规输入通过与受控违约失败两侧；门禁自身出错（缺依赖、加载失败、异常）按失败处理，不按通过处理。
5. **资源有主。** 测试只动自己的临时目录、进程与端口；结束时释放自己启动的东西，不清理别人的。
6. **失败说清范围。** 通过、失败、未运行分别记录；环境缺失不是通过，超时不是通过。

## 怎么跑

- 开发自保：只跑受改动牵连的套件，例如 `node --test requirements/<package>/tests/NNN.test.mjs`，或 `node scripts/verify.mjs --suites <package,...>`。
- 提交前：`npm run format-build-test`。
- 发布：`npm run verify:release`。
- 全套 `requirements/**/tests/run.mjs` 是发布口径，不是每次改动的自保口径。

## 怎么报告

- 说清改了什么、在哪个 HEAD 或 build generation 上跑了哪几条、红还是绿、还悬着什么。
- 不设证明栏、验收栏、witness 表；不数条款、不数基线。
- 测试绿不等于产品做成；种子用户体验验收另走专门通道。

## SPEC

条款编号只用于测试标题锚点（`WHAT[<package>-NNN]`）和包内导航，不是产品宪法。

### [001] 按承诺与副作用选择检查

按被验承诺选边界。层级标签、措辞扫描不能替代对边界的判断。

### [002] Long Stroke 的生命周期范围

Long Stroke 从单一入口启动，在同一物理环境的单次生命周期内完成；相互独立的端到端场景可在隔离环境并行。

### [003] 检查选择而非固定阶梯

不要求 Pure → Temporal → Adapter → Long Stroke 逐级通过。局部验证如实报告范围；not-run、failed、passed 分开记。

### [004] verifier 必须可红

测试必须能因目标要求被违反而失败。无关的缺依赖、加载失败、异常不算有效反例。

### [005] 检查异常必须失败

门禁、运行器与验证设施遇到损坏数据、协议失配或未知异常时停止并报失败；清理失败也报，不吞原始错误。

### [006] 因果推进

挂死监测按距最近一次真实进展的静默时长判断，不凭总时长。达到静默限值时先报告目标与当前等待，再按 [008] 收尾并非零退出。

### [007] 虚拟时间与资源收尾

逻辑时序用显式虚拟时钟推进，同一条因果轨迹必须可重放；真实计时器、事件循环与进程回收用物理观察，固定 sleep 不能证明状态已到达。

测试与夹具按作用域释放自己持有的资源，或明确移交继续运行的工作；正常结束、启动失败、异常、取消与超时都要走完这条路。`Promise.race` 不自动取消另一方，强制退出也不等于释放。清理失败如实报告，不改写成通过。

`Verification/TemporalSurface.js` 是这条规则的 JS 边界：虚拟定时器与时钟（`createVirtualTimer` / `timerDelay` / `timerAwait` / `timerCancel` / `timerAdvance` / `timerNowMs` / `timerDispose`）与 journal 句柄（`openJournal` / `resumeJournal` / `journalDispose`）都按句柄持有、按句柄释放。行为见 [007](tests/007.test.mjs) 与 `support/temporal-harness.mjs`。

### [008] 断言对照行为

断言覆盖合同要求的结果、顺序与副作用；合同规定精确结构或序列化文本时完整比较。判定依据不照抄内部实现，也不因通过而放宽。

`Participant/Provider/Attempt/Fallback/ProviderFailureSurface.js` 的失败预算推进属于此条：断言只对可观察的失败计数、身份与拒绝结果，见 [provider-attempt-recovery](../provider-attempt-recovery/WHAT.md) 的测试。

### [014] 发布级真实宿主验收

真实宿主的端到端场景归发布验证，按 [002] 的范围跑；不在日常改动里重复考古。

### [009] 门禁命中真实路径

静态门禁的路径、匹配规则与入口对应实际检查范围。必需目标缺失、被规则漏掉、或路径不存在而空跑，都报错；合同允许为空的集合按合同处理。计划可达不等于用例已执行。

### [010] 判据不放宽

不放宽现行合同已定的判据，不缩小它要求的范围，也不把本该阻塞的问题降为不影响通过。补充或重构测试、做局部验证，都不需要先改规范。删冗余断言时保留仍有效的保护；发布验收不得挑重跑结果掩盖未解决的失败。等覆盖对照要保证场景、断言、样本与缩减能力一致；减少覆盖、增加跳过或压低预算，不算提速。

### [011] 覆盖率分母完整

覆盖率分母涵盖全部生产模块，并与生产模块清单及当前产物核对；编译器运行库、外部依赖、测试与工具脚本不计入。未加载的生产模块以 0% 计入，不为填分母而全量预加载，也不擅自排除模块。

### [012] 不设行数门禁

门禁只针对语义违规、架构越界或规范不变量。不按文件行数设硬门禁或警告，也不为证明政策存在而增设机械扫描。普通行数统计可以用于讨论。

### [015] 日志观察器

观察器只把完整、合法的 `Fact` 记录认作事实，不按正文关键字猜测。多字节 UTF-8 与未闭合行要等到行结束符到达才消费并提交位点。非法 JSON、`event_id` 冲突、文件身份替换或已消费前缀截断必须报错。多写入者交错时仍按日志顺序完整消费，位点单调前进，通知与消费一致；关闭后停止监听。原子追加由 `durable-events` 的存储合同负责。

### [016] 输入版本与结果适用性

工作树验证在运行前记录输入摘要，阶段之间重新采集并比较；发现变化即报失败，不把后续阶段算作同一版本。既有结果只适用于它的实际输入；边界采样证明不了阶段内从未变化。稳定发布用显式准备、与并行编辑隔离的源码产物构建。耗时对照记录前后版本，固定被比较改动之外的运行时、工具、依赖、输入、并发、预算与缓存条件，并核对用例身份；数量相同不足以说明范围一致。

### [017] 日常与发布入口

日常入口依次执行格式、静态检查、构建、unit 与 integration；发布入口另加 Long Stroke 与打包。按 [001] 可只跑受影响的套件。完整发布结论要有全部适用阶段的结果。

### [018] 不另造编译器扫描

全仓不自建 FCS 扫描，不为取证额外启动或插桩编译器；正常构建使用 FCS 不受影响。`scripts/compiler/Checker.fs` 与 `scripts/compiler/toolchain.mjs` 可以调用编译器 API，但同样不新增扫描取证入口。

### [019] 断言行为，准备有主

优先断言可观察行为；源码扫描只用于明确的静态约束，不按词形猜业务，也不把合同未限定的内部写法当验收条件。昂贵的不可变准备可以复用，但要按失效条件校验版本、输入与产物。无关用例不互相污染可变状态、权限或可写目录；共享资源的场景由夹具明确所有权与收尾。收益计入准备、失效、清理与维护成本；共享夹具或缓存的新增复杂度要有当前需要或实测收益。

### [020] 属性测试

输入生成器只构造合法、边界或明确非法的输入，不计算预期结果，也不重建被测状态机当判定依据。无限或组合爆炸的输入域固定 seed、限定预算，失败时输出可重放的缩减路径；有限小域优先穷举。随机样本不代表穷尽，判定依据的独立性要能说明。

### [021] 范围与结论

报告原定范围、实际完成范围与未完成原因，区分「被测对象违约」与「验证没得出结论」。未执行、无结论和范围外事项不算通过；局部通过不说成整体验收通过。耗时从入口启动计到结果排空和资源回收完成，包含准备；unit 与完整流水线分开报告。测试正文时间或 CPU 总和不能代替整套实际耗时。运行器的嵌套监督把子进程 stdout/stderr 解码成 UTF-8 诊断文本后转发，不继承外层协议流；`node:test` worker 的 stdout 只走原生结果协议，诊断走 stderr。权威结果只来自独立 IPC 与完整收尾证据。
