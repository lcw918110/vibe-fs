# 为什么采用专席 Advisor

LLM 对完成当前 Scope 所需计费回合的估计不下降，说明其预期工作量没有收敛。系统无需推断模型为何这么估计，只要按照公开规则触发咨询。工作模型知道这个后果，也可以自行权衡报数；整数递减至零的约束已经足够明确。

第二意见需要背景，但不应把整份对话重复塞给顾问，也不应让顾问擅自操作工作区。系统先在隔离的短命工作者会话里询问真实困难，交给同一专席顾问确定还需要什么背景，再用工作者当下最新的请求视图取得材料。顾问最后结合两段回答提出建议。参与模型只看到自然的问答，不必理解这四段调度机制。

把 Advisor 固定给一个工作 Session，是为了积累此前咨询的上下文。它自己的历史和会话身份持续存在；单次 Process 和临时工作者问询则有独立的生命周期。二者不能混为同一张记忆表。

零工具不是靠告诉顾问「不要用工具」实现。真正的顾问 Host 配置、产品准入与执行前门禁都拒绝工具。相反，隔离问询需要保持正常 Provider schema，借执行门禁实现只读，才能不破坏来源对话前缀。

顾问的文字是建议，不是操作员命令。发送、排队、物理接纳是不同事实。迟到回答不能跨越新的 Scope。模型请求已经发出但结果未知时，不能为了追求「一定完成」而冒险重发、产生第二次计费；跨崩溃的完整恢复仍需相应持久证据。
