# requirement-system 测试说明

规则以 [WHAT](../WHAT.md) 为准。规范文档和测试组织是本包的处理对象：给检查器输入合法、违约的文档或测试文件，检查它的输出，属于行为测试。

- `001`：条款 ID 的唯一归属；不同编号但语义重复，需要人工审阅。
- `004`：测试标题恰有一个主条款锚点；检查多行声明、模板标题和缺失／重复／错误锚点。
- `005`、`007`、`008`、`011`：正式标题的位置、定义／引用区别、引用格式及提案排除；迁移包只允许 AXIOMS 的 SPEC 定义条款，旧 WHAT 不能继续定义。
- `006`：理由、指定规范文件与测试目录的存在及类型，含缺失、错误类型反例；新文件缺失时不能以旧 WHAT 替代。
- `017`：扫描当前全树；用隔离样本证明条款删除后遗留测试会被报告，包括嵌套目录。迁移包按 AXIOMS 发现条款，保留原测试锚点，拒绝双份定义及旧文件回退。
- `018`：文件编号对应存活条款，同一条款不分散到多个文件；不要求每条都设测试文件。

`support/structure.mjs` 是实际被 `017` 执行的检查器；反例用例调用同一份检查逻辑。测试声明用语法解析识别，避免注释和示例字符串误报。当前识别 `test`、`it`、`integrationTest`、`e2eTest`、`releaseTest` 及其 `only/skip/todo`；任意别名、自定义包装器、动态生成的条款编号尚不构成完整证明。

`002` 的组织权归属、`003` 的公理地位、`010` 的语义历史排除、`015` 的原子闭环，需要人工审阅，未保留只验证常量、关键词或某一句话存在的占位用例。其它条款的机器检查也仅覆盖可识别的格式，不能识别无编号的隐性规则或判定文字是否等义。缺口记在 [GAP](../../GAP.md)。

统一运行方法见 [02 测试说明](../../verification-system/tests/README.md)。
