## 检查器边界

- 边界扫描器用已知模式与部分语法分析；注释、字符串与普通字段访问可能误报，任意别名或动态构造可能漏报。文件名含 `domain` 或 `interop` 本身不算违规。
- 登记检查识别正式标题，正文引用不会创建命题；import 按实际调用文件位置解析。编译项目纳入检查依赖当前项目文件格式。
- `js-contract.mjs` 检查当前值结构；普通业务字段不因名字像编译器字段就被禁止。递归范围是数组元素与纯对象的可枚举自有字符串键值；继承、非枚举属性、访问器、跨执行上下文的特殊值与业务语义不在其内。
- 链接检查覆盖字面相对导入与转导出，模块实际加载补充验证初始化与导出歧义；计算路径、外部包选择与只在调用时才触发的依赖仍需各自领域的运行观察。

## 运行

先 `node scripts/build.mjs`，再经正式运行器跑六个条款文件：

```sh
TESTS_MJS_FILES="$(rg --files requirements/js-semantic-surface/tests | rg '/[0-9]{3}\.test\.mjs$' | sort | paste -sd, -)" node requirements/verification-system/tests/run.mjs
```

当前两个 TODO 会让正式入口返回非零。直接 `node --test` 只用于诊断，它把 TODO 排除在失败之外，零退出码不算通过。
