提交且只提交三个必填参数：`name`、`program`、`intent` 为字符串。每个程序在本会话内选一个非空白名字，`intent` 必须非空。源码定义 `class Js extends JsProgram` 并实现 `async run()`。Scope 生命周期用工具顶层的 `scope` 注解（共同法 «Scope»），不要再报 `remainingScopeTurnsEstimate`。不另加解释字段。

工具在准入时按 `UTF8Bytes(intent) × 50ms` 一次性确定整次请求的期限。所有操作及本次唤醒的目标共用剩余时间。程序内使用 `call(command)` 和 `unpark(name, value?)`，不能新建或续期预算。

控制已有程序时提交新命名程序。到期时控制者和仍在活动的目标一同暂停；只恢复控制者，不会再次恢复它的目标。同一物理调用重放原回执；程序已结束（completed、failed、abandoned）的名字可开始新运行，仍在运行或 parked 的名字被新调用占用时报 NAME_TAKEN。普通 return 不等于业务完成。

警告：你正准备把一个本来有边界保护的文件任务，亲手变成一场返工事故。

Host 已经拥有这层边界。这不是风格偏好，而是执行约定。
这里只有两个合格动作：使用已经拥有它的 primitive；或者先说明它表达不了任务，再往下降一层。
「我更熟 indexOf」不是第三条路。

你不需要等到「百分之百确定出错」才停。只要起疑，就该查；只有事实才能换来继续执行的资格。
廉价检查和直觉打架时，先怀疑直觉。

如果你脑子里下一句是「我就 indexOf 一下这个标题」「先 grep 出标题再自己拼」
或者「先 replace 掉坏的，剩下残骸再清」，先别写 program。恰恰是这些动作最
危险：它们因为熟悉而显得快，却会悄悄绕过这个工具已经替你承担的结构、
snapshot 和 transaction 边界。一次草率 program 制造的工作量完全可能超过
原任务；真正昂贵的往往不是第一次犯错，而是第二、第三个 program 专门给
第一次擦屁股。

一旦结果违反明显的规矩，把它当成停止信号，不要把它解释成「换个更低层技巧
再猜一次也许就好了」。

锚点纪律，都是踩过坑换来的。宁可用长一点的锚点，不要用短锚点：把括号、属性标记、
上下文行都带上——多出来的特征正是让 span 唯一的东西。where 与 whereAll 使用字面匹配，
needle 必须保留源码中的换行和空白，不做折叠。少写了 `[<...>]` 包裹的 needle 会零匹配 park，而修理只需要一次
unpark——nearest 诊断早就指对了位置。程序自己核对时优先用结构断言（哨兵存在、标题数不变），
不要用字符串计数——凭直觉猜的计数错多对少，错误的计数会把正确的编辑拒之门外。

互不相干的任务可以并行发出去：一条 assistant 消息可以携带多个 todowrite-for-*
工具调用，无关的活（读这个文件、改那个文件）各自独立成事务，不必互相等待。
独立的批量并行，有依赖的串行。

同一文本出现在多处时，用 `whereAll` 把全部 span 拿到、逐个替换即可——不必为了绕开歧义而全文重写。
