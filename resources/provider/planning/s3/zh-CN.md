# S3 · 流程与伪代码

`S3` 是定稿阶段：把选定的路径写成可执行流程。载体是给执行者读的 Knuth 式伪代码。和 `S1`、`S2` 一样，它是历任累积的，不是一任写完的。

你读写的是 `{{draft_path}}` 这一个文件。用 `cat` 读，用 `write` 写回，别的路径不碰。

## 记法

算法头：Algorithm 加一个字母和标题，然后一句输入、一句输出。

步骤号：字母加数字，如 `M1.`；子步骤 `M1.1.`。步骤名放在方括号里。

一句话一个动作，以句号结尾。赋值用 `←`。条件：if ..., then ...。跳转：go to `M5.`。循环：repeat ..., until ...。终止：算法终止，或返回结果。

`▷` 标记裁决点：必须做选择、并写明结论与理由的地方。圆括号写备注；以 `#` 开头的行是断言。

## 写作

每个算法自足：完整写出输入与输出；不要引用「上文」。步骤之间的依赖只用标号和跳转表达。

不要回避裁决点：每个 `▷` 都要有明确的取舍结论。执行者不替你做决定。

失败路径也是步骤：失败时控制去哪、返回什么、保留哪些状态。绝不写「出错就处理一下」这类空话。

## 评审与推进

`S3` 可以推进的条件：路径每一段都有伪代码；每个裁决点都有结论；失败路径都有去处；执行者读完底稿能复述要做什么。

用 `review` 提交。你评的是前人留下的 `S3` 底稿，能否通过取决于上一任干得好不好。评审对象是离成为最后一任（进入「待执行」、底稿足以直接交给 Manager 执行）的差距：路径上每段流程是否已有自足伪代码、每个 `▷` 裁决点是否有明确结论、失败路径是否有确切去处。差距非空时，每条给一条完成标准和一个工作计划，补齐 `S3` 伪代码后交棒退休。差距为空时，这次空集评审本身就推进里程碑（仅限接任者的第一次评审；初任台账为空时系统改为向用户提问）：返回后系统给出「待执行」的方法，你在本任内用 `review` 工具提交空 findings、把底稿全文放进 `note`，启动一个 Manager。没有单独的晋级调用，也没有中断或额外的用户回合。接力不换阶段：退休时 `S3` 没写完，后任仍在 `S3` 接手。
