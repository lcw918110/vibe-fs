# 万象通

万象通是**宿主语义的唯一住所**，位于主工作树，与 `wanxiangli/` 并列，暂不开独立仓库。它把 OpenCode、omp、Cline 等宿主的消息、工具调用与生命周期事件翻译成产品与万象理能用的形式，再把结果翻译回宿主。宿主特有的错误文案、协议差异、配置名与环境变量也留在这里。

## 判据

一句话：这是**宿主特有语义**吗？

- 是 → 万象通。翻译可以厚、可以丑，这是它的光荣。
- 不是 → 按实际归属判断：领域状态与规则归万象理，提示词、工具资源、角色与支撑程序等通用职责留在实际主人手里，不因为「跨宿主通用」就一律塞进核。
- 谁也不认领 → 大概率该删。

## 归这里

- 消息长相：为什么消息长得像用户、角色标记与前缀如何编码、内容块如何拼。
- 生命周期：hook 先后、session 创建与结束、父子会话、中断与终止信号。
- 工具面：工具名、参数与返回形状、错误措辞、provider 协议与 wire 解码。
- 配置与环境：宿主配置名、环境变量、安装与加载方式。
- 翻译带来的在途状态：请求与应答的配对、待发队列、重试簿记。

## 不归这里

- 领域状态及其规则，归万象理。
- 模型要看见的提示词、角色说明、工具资源，归本仓产品面。
- 跨宿主通用的协作顺序，归万象理里的组合者。
- 与宿主无关的支撑程序（构建、打包、脚本），留在其实际使用方，不借「通用」名义搬家。

## 依赖方向

万象通只消费万象理的 npm 公开入口（`exports` 与 `.d.ts`）；本仓与万象通都可直接消费万象理。万象理不认识万象通，也不认识本仓。适配层可以拥有翻译所需的状态，但不复制领域账本。

## 现在在哪里

本目录目前只有说明，没有宿主适配程序。宿主代码仍在原处：

- `src/Wanxiangshu/OpenCode/`：编解码、hook、信号、工具面与插件入口。
- `src/Wanxiangshu/Omp/`、`src/Wanxiangshu/Composition/Omp/`：omp 扩展适配。
- `src/Wanxiangshu/Composition/Plugin/`：插件装配（OpenCode 入口侧的启动接线）。
- `src/Wanxiangshu/Foundation/`（如 `HostModel.fs`、`HostSessionPort.fs`）、`src/Wanxiangshu/Composition/Turn/`：仍混有宿主接线与宿主专名。
- `scripts/`：宿主侧辅助脚本。

核侧 `wanxiangli/src/host-omp/` 已不存在（现行 `src/` 下无 `host-*` 目录）。

这些是现状，不是已经完成的三层切换。
