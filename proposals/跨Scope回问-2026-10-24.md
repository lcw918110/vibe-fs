# 跨 Scope 回问：向过去的自己澄清

2026-10-24 设计稿，2026-10-29 按现行实现重写。**现行协议见 `resources/provider/host/scope-protocol/` 与 `wanxiangli/src/pair-hint/AGENTS.md`**；本文只留仍成立的行为约束与未完成边界。

## 1. 用户真正要的行为

重锚（`scope.kind=resetScope` 注解）之后，旧 Scope 的过程上下文不再发给模型；但有些判断需要旧 Scope 的材料。`askPreviousScope(question)` 让工作者向「重置前的自己」提问：系统以旧 Scope 的真实请求视图发起一次短命只读咨询，把回答带回当前 Scope。

要点：

- 交接字段现行名是 `newScopeGoal`／`oldScopeVerboseVerbatim`（旧稿的 `newScopeObjective`／`oldScopeVerboseVerbatimExperience` 已废）。
- 首问义务如何强制以实现为准；本文不另立规则。
- 旧 Scope 的边界必须是真实 reset 屏障，不能按消息下标或游标猜测；找不到分界就拒绝咨询。

## 2. 现行入口

- 重锚：任意工具上的 `scope.kind=resetScope`（交接写 `oldScopeVerboseVerbatim`）→ `ScopeReset.commit`；没有独立 `resetScope` 工具。
- 回问：`askPreviousScope` 仍在，登记为工具准入（`src/Wanxiangshu/Execution/Tool/Admissions.fs`），属 `scopeProtocol` 权限族。
- 投影：PairHint 保存唯一最新 transform view，`preceding-scope` 视角从最新 input 找最近一次真实屏障，只交出屏障前的内容（细节见 `Scope进度自评-专席Advisor-双重压缩-2026-10-25.md` §4）。

## 3. 已成立

- OpenCode：旧系统/消息/型号回放、只读模型回问与真实 steer 实测通过。
- OMP：真实 SDK + 本地 SSE Provider canary 证实冻结完整原生请求（含旧工具目录）、实际临时 Provider 请求替换、旧我回答经真实 agent steer 送达、幂等重放。
