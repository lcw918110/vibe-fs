# 持久审计的用途、取舍与后续调整

2026-11-01。只读研究基线：主体 `e90cdc7d8243a98dd7b53571850e9857c40efba4`，库 `2dd1ff8c5dd7efa8948b7fb5c31c99fd057cdfed`（0.84.0）。本方案未改程序，未运行测试或测量性能。下面是建议，尚未实施。

## 当前决定

用户随后明确要求回到拆库主线，审计先保持现状。本文用途调查保留；下面的退出建议及 A/B 工作包均暂缓，未实施，不是任何后续拆分的前置条件。新的施工安排见[下一批完整职责拆分计划](下一批完整职责拆分计划-2026-11-01.md)。不得从本文推导停止审计写入、改变错误结果或删除历史数据的授权。

## 当时的建议（已暂缓）

分两个工作包退出 JS 文件变更审计、JS 程序生命周期审计的新增生产写入，保留历史读取兼容。先文件记录，后生命周期记录；每包做完即可停止。不要将它们拆为新的库、codec 或队列入口。

依据是当前可用收益和实际代价：两条链都有真实写入，也提供一些手工排障材料；但尚无产品查询、恢复或决策功能消费它们。记录的关联和存留又不足以承担完整历史审计。为这些材料付出的写盘、等待、全文存储以及操作已完成后仍报审计失败的代价，缺少相称的产品需要。

本建议只针对下述两条 JS 审计流。Journal、Work/DurableWork、Trace、交付与其他确实服务恢复和用户委托的持久事实不在退出范围。文件效果回执和 Program 的在途状态同样保留。

## 目前实际有什么用

| 内容 | 实际能力 | 当前局限 |
| --- | --- | --- |
| 文件 Prepared/Committed | 每笔修改可配对；Prepared 保存工作区、路径及部分原始/新文本；失败回执给出事务和事件 id | 没有 session、程序调用、tool call、provider run 或发生时间。只能确认记录的配对，无法可靠归属整次程序执行 |
| Pending 投影 | 从已载入历史重建尚无配对 Committed 的 Prepared | 当前查询者是 TransactionSurface 和测试；没有找到产品查询、提示或恢复入口。Pending 不能判断物理效果是否发生 |
| 生命周期 Parked/Unparked/Abandoned/Reaped | 保存事件、程序名字、session 和时间，可人工看粗粒度轨迹 | 不保存暂停现场、continuation 或恢复值；投影只更新 Head，没有业务读取者 |
| 一般事件读取 | 开发者可经 EventStore 的通用读取能力，定位仍在加载范围内的事件 | 不是操作历史产品界面；没有按程序调用配对和解释审计的查询路径 |
| 故障诊断采集 | 每个工作区复制 mtime 最新的一份物理 ndjson；其中可以包含审计原件 | 不收齐所有 writer/分段，不保证 Prepared/Committed 都在。events-tail.json 只提取末十行 id/type/fact_type |

事实位置：[记录和追加](../src/Wanxiangshu/Repository/Programming/Js/TransactionStore.fs)、[投影](../src/Wanxiangshu/Repository/Programming/Js/IntegrationRules.fs)、[测试查询面](../src/Wanxiangshu/Repository/Programming/Js/TransactionSurface.fs)、[一般事件读取](../src/Wanxiangshu/Persistence/EventStore/Surface.fs)、[诊断采集](../scripts/diagnostics/collect-incident.mjs)。

### 它们没有提供什么

- 文件记录不是完整撤销日志：Rewrite 保存前后文本，Create 保存新文本，Remove 不保存删除的内容，Move 以 OriginalText 保存目标路径。不能据此承诺所有操作可恢复原件。
- Prepared 是写前发起追加，终局才等待；不保证先落盘再改文件。没有 Committed，可能是物理失败，也可能是物理成功而记账失败或未知。
- Committed 说明对应记账路径已走到写后，不代表此后文件未被其他操作改动，也不是无限期历史保存承诺。
- 生命周期记录不能在进程重启后恢复程序现场。现场由库中的 Program/Run 内存对象持有；当前 pending 提示、交付前检查读取 JsPrograms.pendingNames，不读审计流。

来源：[持久变更形状](../src/Wanxiangshu/Repository/Programming/Js/Transaction.fs)、[文件调用和效果收集](../src/Wanxiangshu/Repository/Programming/Js/ToolsBindings.fs)、[程序状态](../wanxiangli/src/program/Run.fs)、[pendingNames](../src/Wanxiangshu/Repository/Programming/Js/Programs.fs)、[实际提示消费](../src/Wanxiangshu/OpenCode/Host/PairProgrammingThoughtTransform.fs)。

### 存留不是审计档案

当前按整个 writer 的活动日期筛选可读历史，保留 UTC 今天、昨天及更晚日期。它不是按每笔审计记录计时；活跃 writer 的早期记录也可能一直在读取范围内。事务尾行没有 ObservedAt，活动判断会回退到文件 mtime。

读取过滤不等于物理删除。本轮沿实际路径没有找到按这项 retention 删除过期 writer 文件的生产调用。因此 Pending 从 Current 消失，不说明磁盘原件已删除；磁盘原件仍在，也不说明一般 EventStore 仍会加载它。

来源：[活动及日期规则](../wanxiangli/src/retention/WriterRetention.fs)、[实际读取筛选](../wanxiangli/src/segments/SegmentedReader.fs)。不据此推测实际磁盘占用或提出自动清盘。

## 保留的代价

当前接入审计的每笔成功 write/rm/mv 发起两次 EventStore append；mkdir 不走这套记账回调。Rewrite 重复存前后全文，Create 存全文，没有在这些 payload 上做内容引用去重。append 经过共享存储锁和持久追加链；程序终局等完已发起任务。本轮只确认成本结构，没有测延迟、文件大小或占比。

记录错误能影响已经完成的操作：文件变更落地后，记账失败或未知仍使工具失败；上一轮已修复拒绝时漏报效果的问题，但等待和失败耦合仍在。生命周期记录错误还会附加 lifecycleError，使已 completed 的程序被主体解释为失败；会话已关闭后 Reaped 追加失败也会抛错。

审计与其他事实共用 writer 文件。坏 UTF-8、半行等物理损坏可能阻断整个存储加载；事务 payload 的语义错误另有 integration/cut 处理，实时追加还可能触发原有 fatal 路径。不能把这些情况都说成一个普通查询失败。停止新增写入也不会修复既有损坏。

来源：[存储追加](../src/Wanxiangshu/Persistence/EventStore/Store.fs)、[失败码](../src/Wanxiangshu/Repository/Programming/Js/Failure.fs)、[Workflow](../src/Wanxiangshu/Repository/Programming/Js/ToolWorkflow.fs)、[会话关闭](../src/Wanxiangshu/OpenCode/Host/PluginSessionScope.fs)、[历史验证](../src/Wanxiangshu/Persistence/EventStore/IntegratorEngine.fs)。

## 三种选择

| 选择 | 收益与投入 | 判断 |
| --- | --- | --- |
| 原样保留 | 保留现有人工排障材料，同时持续承担现有成本 | 不建议作为长期默认。不能只凭已经实现就继续付费 |
| 做成正式操作历史 | 先有真实用户需求，再设计调用关联、查询、存留、内容保存范围及审计失败的处理 | 只有明确需要查看历史时才值得安排。它仍不自动等于撤销或程序恢复；本轮不补一组字段冒充产品化 |
| 停止新增写入，兼容读取旧事件 | 减少生产记账、全文副本、等待及审计失败耦合；已有原件继续保留 | 推荐。分两包实施，分别保留真实文件回执和程序生命周期能力 |

不建议另建 best-effort 审计存储、通用审计总线或静默吞错开关来维持当前材料。若将来出现明确排障需求，按真实问题选最小记录，而不是先保存更多全文。

## 工作包 A：退出文件审计生产链

### 目标和边界

write/rm/mv 仍按现有 as-is 语义执行，成功和失败都报告已落地效果。取消额外 Prepared/Committed 写入及其终局等待；不改物理 FileSession、角色权限、读快照、错误码或普通文件失败处理。

切换时使用既有正常关闭和排空流程；在途旧程序仍完成原结算，不清空追加队列或强杀宿主。

1. 从生产接线 `PluginHostInterop → ToolRegistry → OpenCode/ToolHost → ToolWorkflow` 移除 IJsTransactionPersistence 透传；同步 fsi 和原测试消费者。只删事务审计参数，不删其他 EventStore 用途。
2. ToolsBindings 不再提供审计 before 回调，after 继续收集已落地 mutation，read 继续收集原读取观察。FileSession 已允许省略 before；先使用现有接口，不改库公开契约。
3. Workflow 保留 staging/reads、效果附加、返回值检查和观察行为，删除 JsAsIsLedger 构造与 Settle；移除不再有生产消费者的类、写接口、写编码和审计专属失败通路。旧兼容解码需要的形状保留，不能按名字整删 Transaction.fs（里面还有文件计划等职责）。
4. 原 ledger 拒绝回归和强制审计追加测试随生产职责退出而删除或改为真实需求测试；不为继续养测试留下审计写者。上一轮修复在退出前仍保证失败回执可信，不构成长期保留队列的理由。
5. 首包保留旧词汇、decoder、现有 integration rule 与投影作为只读兼容，停止新业务依赖 Pending。它有明确出口：在不改变旧日志接受/重放行为的前提下，后续可只保留历史解码，去掉无用投影；不在首包同时改重放规则。

### 检查范围和收尾

- 复用真实写入/创建、rm/mv、部分失败仍报告效果的相关用例；不重跑整个文件系统回归。
- 检查实际生产工具路径不再产生 JsTransactionPrepared/Committed，而不是只让测试传 None。可用既有 append 观察夹具，确认文件成功不再被事务审计拒绝影响。
- 用静态历史夹具覆盖旧 Prepared、Committed 与未配对 Prepared，重新打开原存储仍成功；不通过新生产写接口造“旧历史”。保留旧 payload、parents 和事件身份，不删原件，不回滚或补提交。
- 正常主体构建和实际 pack 消费；若库无改动，维持现有候选。隔离树完成后同步原目录，只检查合入影响。

## 工作包 B：退出生命周期审计生产链

A 完成后独立处理，不与文件审计共用一个新对象。

1. 从 PluginHostInterop、ToolRegistry、ToolHost、Workflow 移除 IJsLifecyclePersistence 接线和审计 callback。保留 program/runtime 的通用 lifecycle 能力与真实状态迁移，不因此修改库契约。
2. 从 PluginBoot、PluginRuntimeScope、PluginSessionScope 去掉为 Reaped 审计而传递的能力及关闭后追加；保留 closeSession、等待退出、资源释放和原关闭顺序。关闭错误不能被一并吞掉。
3. 删除无消费者的宿主写接口、写编码和审计专属错误映射。保留旧四类事件的已知词汇、解码和现行 integration rule 作为历史兼容；不顺带动文件审计兼容。
4. 保留真实 park→unpark、park→abandon、session close 和 pendingNames 提示测试；将 041 等用例中“写下事件就能恢复现场”的说明改正。检查生产不再写 lifecycle 审计，旧事件日志仍可打开。
5. 按 A 的构建、打包与合回步骤交付。不把没有审计写入解释为生命周期行为消失。

## 后续拆分边界

这两包的结果应是退出不合算的生产链，而不是新增一个 audit/ledger 包。保留的历史兼容先就近放在现有 JS 事件职责中，不因三个文件同在一处就建 npm 子入口。

文件物理行为继续由现有 runtime/FileSession 拥有；程序在途与暂停行为继续由 program/Run 拥有；主程序组合本次操作的效果回执。after 回调加本次 staging 目前能明确表达这项协作，不预定再公开 effects-store、cache 或报告对象。只有整理后仍存在完整、可独立使用且能减少适配的状态 owner，才讨论并入已有入口；不按行数和剩余文件数选择下一刀。

WarmStart/Semble 和问卷能力继续暂缓。停止新增审计、历史读取兼容、删除旧磁盘记录是三件不同的事；本方案只推荐前两项，不安排历史文件删除，也不把本研究视为程序施工授权。
