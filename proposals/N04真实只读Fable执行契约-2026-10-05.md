# N04：真实只读输入的执行契约

2026-10-05 调查定稿，2026-10-31 按当前代码改写。**本文是设计记录，不是验收证书**：实现见 `scripts/lib/verification-readonly-inputs.mjs`，产品条款见 `requirements/verification-system/AXIOMS.md`（016）。当前实现只在 macOS 可用；Linux 与 Windows 在消费前明确拒绝。

## 1. 做什么

验证编译时，把四个已准备好的 owner（source、SDK、tools、project）的原目录整体替换成一个只读卷视图，编译与消费者只经该视图读输入，写产物落在视图之外的自有目录。退出时先停止新接入、取消并等已登记消费者排空，再 detach，最后核对原目录身份与完整库存恢复。

四个 owner 的根必须是同一父目录下四个不同兄弟目录；视图挂在父目录上，所以 mountPoint 本身也被替换。`assertReadonlyVerificationInputs` 只对登记过的 exact owner 生效，且要求输出目录不在视图内。

## 2. 所有权转换

原目录 owner 的合同要求 parent/root 仍是分配时的 dev/ino。挂载让同一路径解析到卷内根，旧 owner 此时拒绝是正确行为；不能更新旧 inode、只比较内容，或加接受任意新 inode 的兜底。

1. 原 prepared owner 完整校验；捕获成员并制作镜像，核对镜像内容与原 receipt。
2. 在固定绝对路径建立只读挂载，记录 exact image、device、mountpoint 身份。
3. readonly view 显式接管执行期路径，编译只消费该能力；原 owner 不在此阶段执行旧 inode 断言。
4. 编译与消费者实际退出、进程组回收、pipe 排空后，校验并 detach owned device。
5. 确认原 parent/root dev/ino 与完整库存恢复，原 owner 才能重新 revalidate/dispose。

这是物理能力的所有权转换，不能靠展开旧对象或替换 root 字段伪装同一 prepared receipt。布局无法保证时明确拒绝，不做全局路径替换。

## 3. 镜像与挂载

- 两阶段：先 `hdiutil create -format UDRW` 生成 capture，再 `convert -format UDRO` 得到最终镜像；只有最终唯一 UDRO 才能 attach。
- 每步都核对：镜像文件仍是自有 inode、目录内没有未确认产物、capture 阶段没有残留挂载。
- attach 后核对 `image-path`、`writeable=false`、`image-type=UDIF read-only`、唯一挂载点与 exact `/dev/diskN(sM)` 设备。
- 视图内 `revalidate()` 每次核对镜像身份、挂载点身份、四个 root 身份、owner 选择与完整库存（路径、mode、字节 sha256、链接目标）。
- 消费登记：`consumeReadonlyVerificationInputs(view, operation)` 在视图关闭后拒绝新消费者；scope 结束时 abort 已登记消费者并等其 settle。

每命令 30 秒上限，正式监督预算不动。

## 4. 失败与回收

| 失败位置 | 可以做什么 | 必须保留的边界 |
| --- | --- | --- |
| 镜像未挂载 | 按私有身份回收自有目录与镜像 | 不清理已被替换的 parent/root |
| attach 报错、结果未知 | 从真实 hdiutil 记录定位 exact owned image/device；无法确定则保留自有产物 | 命令失败不证明没有挂载 |
| 编译失败或取消 | 先终止并排空 owned 进程组，再 detach | 不能先 detach，让活跃进程读到原可写目录 |
| mount/device 被替换 | 拒绝发布结果，只处理已证明自有资源 | 不按路径删除 foreign mount，不猜 parked 目录 |
| detach 已完成 | 核对原 dev/ino 与库存恢复，再 dispose | 路径不存在不证明原所有权恢复 |
| detach/恢复校验失败 | 清理其它已分配自有资源，聚合错误并保留原业务原因 | 不覆盖原 Error/null，不输出成功 receipt |

失败传播：action 正常返回但消费者失败时，scope 仍以同一 consumerError 拒绝，不发布 action 结果；action 自身再抛值（含 null）时以 `AggregateError` 聚合，`cause` 保留原 action 值，`errors` 精确为 `[原 action 值, 原 consumerError]`。

## 5. 保护边界

UDRO 只保护经该文件系统访问的输入。以下不在承诺内，属于待决项：

- 镜像 backing 文件本身；
- 挂载前就已打开的可写 FD；
- 同权限 actor 的 detach/remount；
- 父路径或链接的 TOCTOU/ABA；
- 整个 OS 的不可改性。

## 6. 阶段矩阵（接入 verify 前要逐阶段核对）

| 阶段 | 固定输入/执行来源 | 可写产物 | 重点绕过面 |
| --- | --- | --- | --- |
| format:check | 捕获源码与配置、选定 SDK/Fantomas、Node/npm/wireit | 自有 CLI/cache/temp、wireit 状态、日志 | PATH 回落、父目录配置、用户 tool cache、旧成功缓存 |
| check | 捕获脚本及 imports、源码/规范/资源、选定 Node/dependencies | 自有缓存和日志 | 原 workspace 的 scripts/lib 或 generator corpus、漏捕获依赖 |
| 单工程 Fable | 四 owner、原 fsproj/props、SDK packs/runtime、Fable 依赖、NuGet 恢复图 | compileRoot 的 seed、JS、HOME/CLI/tmp/cache、日志 | 恢复绝对路径外借、安装回落、DLL 旁加载、旧 dist |
| 全仓 build | 单工程输入加全部 owner graph、build/generator corpus、完整依赖 | dist/staging、合法 build state/cache | 源码闭包漏项、incremental 旧输入 |
| unit | 正式 runner/test/support、实际 build 输出、资源、选定 Node/dependencies | 受控临时 workspace/journal/HOME、日志 | 原 dist、外借 monitor/Node、未声明 OS 命令 |
| integration/e2e | unit 输入加选定 Host/SDK、provider 端口合同与 OS 前提 | 自有 Host workspace/history/journal/database/socket | 环境 Host/模型回落、未绑定网络输入、未排空资源 |
| package | 捕获 manifest/resources、实际 build 输出、选定 npm/归档工具 | 自有 pack/tgz、隔离消费者、日志 | 原 workspace npm pack、遗漏/额外文件、安装网络 |

`scripts/verify.mjs` 目前仍从环境启动 npm、用当前 Node、在 workspace 分配 verify logs，阶段完成后比较输入；没有运行期只读视图。接入按阶段逐个做，一次一刀。
