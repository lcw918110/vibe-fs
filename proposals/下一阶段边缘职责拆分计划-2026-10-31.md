## 3. 第一项：returned-material

### 3.1 对总流程有什么用，边界在哪里

一个参与者做完后，主程序需要保留报告和随报告交回的材料，之后取回、交接和展示。当前 [Foundation/ReturnedMaterial.fs](../src/Wanxiangshu/Foundation/ReturnedMaterial.fs) 统一保存 `{body: string[], carry: string[]}`：body 是报告原文，carry 是材料原文。这个划分由调用方明确提供，不从文字内容推断。

迁走整套表示协议：`encode`、`body`、`carry`、`validate`、`entries`、`fullText`。它没有持久状态；用纯函数即可，不造令牌、WeakMap 或管理对象。

三个相邻职责明确组合：

| 责任 | 所在处 |
| --- | --- |
| 会话交付格、围栏、选材和去重 | 已有 `wanxiangli/delivery`；本轮不改 |
| body/carry 的规范 JSON、读取与原文视图 | 新 `wanxiangli/returned-material` |
| 指令注释、材料表格及 TOML 转义 | 已有 `wanxiangli/llm-text`；本轮不改 |
| 调用先后、完成记录、存储和宿主工具协议 | 现有主体调用方，宿主部分将来按万象通边界处理 |

`delivery` 的 `JsDeliveredValues` 已在生产返回原生 body/carry，并没有保存这个 JSON 协议；所以本项是新职责，不是补接旧库。新模块不依赖 delivery 或 llm-text，二者也不反向调用它；主体继续显式组合。

### 3.2 建议公开接口与兼容边界

```ts
export function encode(body: readonly string[], carry: readonly string[]): string;
export function body(encoded: string): string[];
export function carry(encoded: string): string[];
export function validationError(encoded: string): string | null;
export function entries(encoded: string): { text: string }[];
export function fullText(encoded: string): string;
```

`validationError` 的 null 对应主体原 `Ok()`，错误字符串对应原 `Error`；保持现有两种错误文字。其余函数仍可按原约定抛错，不把读取失败转成空材料。数组为原生 JS 数组，不暴露 Fable list/Result。

必须先把下列现状写成小测试，移植时不顺手统一：

1. `encode` 生成 `JSON.stringify({body, carry})` 的字节，body 键在前。保留每个字符串、块顺序、空串和重复；不 trim，不归一化换行，不排序。
2. `body` 与 `carry` **只检查被读取的字段**。显式 null 返回空列表；缺字段 undefined 或非字符串数组抛错。另一个字段无效不阻止当前字段读取。不能用一次严格 `decode` 替换这两个入口。
3. `validate` 比较重新编码后的完整字符串。键序、额外键、JSON 空白和字符串转义不同，即使解析对象相同也不通过。`{"body":null,"carry":[]}` 可读取 body，但不是规范存储字节。
4. 非法 JSON 的直接读取仍抛错；校验入口仍返回原错误。非对象、数组根、混合元素的数组保留原拒绝路径。测试比较项目自己的错误文字，不硬编码不同 Node 版本的原生 JSON.parse 报错全文。
5. `entries` 只把 carry 依序映成 `{text}`，保留重复；`fullText` 将 body 后接 carry，以 `\n\n` 连接原块，不先渲染 TOML。
6. 完成记录 schemaVersion 仍为 4，存储字节不变，不引入历史数据迁移或新版本兼容层。发现字节不一致先修移植，不改快照迁就它。

`ofEntries` 当前唯一使用方是 [JoinSurface 的输入转换](../src/Wanxiangshu/Execution/Delegation/Fork/JoinSurface.fs)。它是测试 Surface 的 `{text}` 夹具输入，不是新增库 API 的理由。将这段形状转换收回该 Surface，保留原输入错误行为，再从 ReturnedMaterial 的 `.fs/.fsi` 删除 `ofEntries`。生产 `entries` 仍迁入新模块，因为 ToolRegistry 的真实返回会使用它。

## 4. 第二项：keyed-serial

### 4.1 迁走的是跨调用状态

同一会话可能同时收到多次捕获请求。现有 [Context/Trace/Capture.fs](../src/Wanxiangshu/Context/Trace/Capture.fs) 用 `captureTails` 排队，避免两次操作同时根据旧投影分配持久游标。新的实例拥有 key 到完成尾项的映射，负责排队、放行与清理；Capture 仍拥有捕获协议。

```ts
export class KeyedSerial {
  run<T>(key: string, action: () => Promise<T>): Promise<T>;
}
```

只接受 key 和工作函数，不接收 Session、Journal 或 Trace 对象。一次 run 对应一次执行，不合并、不去重；没有公开队列、reset、drain、计数、取消、超时或重试接口。

它与 `bounded-map` 的差别是跨调用、同 key 串行；后者只管单次映射的并发上限。已有 `admission-queue` 管准入/容量/认领，不替代它。也不顺带统一 ManagedChatExecutionFlight、ReconcileScheduler 等领域协调器：它们的失败传播和业务含义不同。

### 4.2 先固定调度细节

- 同 key 按 run 调用顺序执行；不同 key、不同实例独立。
- **同步登记队尾，异步启动 action。** 当前生成的 JS 即使没有前驱，也经过 Promise 微任务后才调用 action。不能把第一项改为同步执行。
- 队尾是独立、最终成功完成的放行信号，不是 action 的结果 Promise。成功、同步抛错或异步拒绝都放行后继；本次结果/错误对象原样交回，不包装。
- A 完成时若 B 已经排队，A 不能删除 B 的尾项。清理只删除仍指向本次完成信号的 key。
- 后继等待 action 结清与放行，不等前一调用者消费结果。不要新增“调用者 await 返回后才开始下一项”的时序承诺。
- 工作若一直不结清，同 key 后继继续等待，其他 key 不受拖累。非重入用法不变：action 可以排同 key 后继，但不能在自己结束前 await 该后继，否则自等待。写清这个限制，不新增运行时警察、跳队或超时机制。
- Capture 原无 journal 直接返回、冲突拒绝、存储错误转换、原文保存均保留。已有 Trace 的生产桥接不变，本项不是首次接入 Trace，也不是 Trace 协议升级。

## 5. 两项共用的构建、接回和交付步骤

继续复用 [前三项计划的施工与交付办法](新边缘模块拆分计划-2026-10-31.md#2-三项共用的施工与交付办法) 及现有脚本。这里补足执行顺序，不新增候选登记系统。

1. **开工时选基线。** 读取两仓实际 HEAD、工作区状态和主体依赖 pin。当前推荐顺序不代表授权同时迁两项；逐项施工。使用隔离工作树与 `codex/` 分支；保留原目录未提交改动。若期间输入变化，只重读影响该项的差异。
2. **一次只改一个入口。** 库 `package.json` 更新 exports、对应 `index.d.ts` 的 files 白名单和 test 列表；版本与自身 lock 同步。`scripts/tests/build.test.mjs` 登记该模块的隔离构建；沿用 `scripts/tests/*-package.test.mjs` 的 npm pack/临时安装模式，添加对应 Node/Bun/TS 消费者。不写新构建器、不让工程跨编译其它模块源码。
3. **先做本模块检查。** 以 returned-material 为例；第二项把模块名换成 keyed-serial。下列路径是未来施工时新增的文件，现在不能直接把命令当成运行结果。

   ```sh
   node scripts/build.mjs returned-material
   node --test src/returned-material/tests/*.test.mjs scripts/tests/exports.test.mjs
   node --test --test-name-pattern='returned-material compiles' scripts/tests/build.test.mjs
   node scripts/build.mjs
   node --test scripts/tests/returned-material-package.test.mjs
   ```

   最后一轮普通库构建用于补齐整个 npm 包要交付的产物；缓存未变模块，不等于要求重跑全部库回归。缺 Node/Bun 环境分别标明，不能算运行过。
4. **得到不可变候选。** 库提交完成后记录完整 SHA，再在主体现有 submodule 检出这一个 SHA；更新 gitlink、lock，`npm ci`，从公开入口接回。版本字符串不能替代 SHA。未来版本号在该项开工时选，不在本文硬编码为永久测试预期。
5. **构建与定向检查。** 在主体隔离树运行 `node scripts/build.mjs`，再运行各节的相关测试。先暂存候选 gitlink，再把库提交中已选定的完整 SHA 填入 `WANXIANGLI_EXPECTED_SHA`；不能从当前安装结果反向生成目标。实际值设置后，后续定向与发行命令沿用同一环境。

   ```sh
   export WANXIANGLI_EXPECTED_SHA='<本项已经选定的完整库 SHA，执行前替换>'
   node --test --test-name-pattern='source checkout' requirements/distribution/tests/011.test.mjs
   node scripts/verify-package.mjs
   ```

   已有 011 的候选错误反例没有变时，不为同一结论全部重跑；改变候选核对逻辑时才重跑对应反例。实际包入口要增加该项有意义的消费，沿用当前 `.verify-library-entries.mjs` 或主体组合探测；不得回退邻仓源码/私有 dist。returned-material 消费明确区分规范字节和显示文本，keyed-serial 消费实际顺序与失败后继。
6. **报告实际范围。** 写两仓提交、build generation、运行的几条命令、红绿和仍未决事项。原 TODO 单列，库侧完成、主体接回、远端可取得和用户真实体验分别表述，不让一种代替另一种。
7. **同步原目录与共享。** 隔离树检查完成后才快进原树，更新该树的固定依赖并按正常入口构建；只重跑受合入牵连的检查。保留用户无关未跟踪文件。正式远端交付必须库候选先可从主体声明的仓库取得，主体引用随后交付；本地提交不冒充已经发布。
8. **每项可以独立停止。** 若需回退，用可审阅提交一起回退该项主体接线、gitlink 与 lock，再按上一候选安装构建；不只降版本号，不把隐形旧实现留在源码作兜底。已经完成的前一项继续保留，禁止重写共享历史或覆盖本地工作。

遇到输入/输出字节变化、时序无法解释、候选无法取得或真实调用无法通过，留在隔离树定位，不启动下一项。计划里的接口是可执行起点；发现边界不完整时先修计划，不靠多加 facade 把差异藏起来。

## 6. 文件锁暂缓，下一次再具体化什么

候选源码是 [Git/IntegrationGate.fs](../src/Wanxiangshu/Git/IntegrationGate.fs) 与 [Persistence/EventStore/ProcessEventLog.fs](../src/Wanxiangshu/Persistence/EventStore/ProcessEventLog.fs)。它们共享 processAwareFs，因此只抽发布锁会留下对日志实现的依赖，边界不完整。

下一次若选择它，应先把下面四点落定，再写实现步骤：

- 共同的进程感知 fs、租约释放状态可以同属一项；仓库/分支锁路径、日志路径和各领域错误结算仍由使用方决定。
- 两种获取策略不同：发布锁用 proper-lockfile 的 50 次退避，日志锁在 30 秒总预算内只重试 ELOCKED；不能为了共用一个函数改成同一策略。
- 目前 stale 为 5 秒、心跳为 1.5 秒；失活 PID 可令 mtime 变旧，但活 PID 不等于锁永不陈旧。owner 文件读写失败的现状也不能被新文档夸成更强的进程身份保证。
- 两处 release 都先置 released，再等待真实释放；第一次失败后再次调用不重试。若要修正这点，应明确作为行为变更，不夹在保持行为的抽取里。

后续最小取材范围是 change-integration/004 的实际锁分支、durable-events/006 的获取与释放失败分支；不为规划先跑互斥实验，更不启动整套发布或日志回归。它涉及外部效果和持久性，待前两项闭环后再决定是否开工。

下一条建议施工指令是：**按第 3 节先拆 returned-material，接回主体并退出旧存储表示算法，保留原字节与读写行为；keyed-serial 和文件锁暂不实施。** 实际开工须满足根规则的迁移前置条件；这份计划本身不代替负责人安排。
