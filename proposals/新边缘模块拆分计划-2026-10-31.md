## 2. 三项共用的施工与交付办法

### 2.1 顺序与工作区

1. 每项各用隔离的库、主体工作树，分支用 `codex/` 前缀。先记录所用两个 HEAD；保留原目录及无关本地改动，不在服务中的树上留下半成品 `dist`。
2. 先补该项最小行为用例，再迁库实现，再接主体；不是先把三份库一起堆出来，最后再接。
3. 每项分别形成库提交和主体提交。当前只完成第一项；后两项等待用户后续安排。共享 package、锁、测试清单的修改顺序合入，不让多条分支各自覆盖版本。
4. 开工只需读取该项源码、直接使用方、局部规则、相关测试与现有构建入口。下面列出的测试是受影响范围，不是要求借机跑全仓回归。

### 2.2 库侧文件约定

每个新模块在 `wanxiangli/src/<模块名>/` 放一份简短局部说明、一个 `.fsproj`、必要 F# 实现、`index.d.ts` 和行为测试。纯计算直接用函数；有界映射的队列与许可由内部对象拥有，不为了统一外形制造公共对象或 Actor 框架。

更新库 `package.json` 的 `exports`、类型文件 `files` 白名单和现有 `test` 文件列表；更新包版本及锁中自身版本。新增入口仍共用整个包的版本，不在此预先指定未来版本号。工程最后一个 Compile 对应公开入口，使用现有 `PackageExport` 能力导出函数，不另建构建器。

把模块加入 `scripts/tests/build.test.mjs` 的隔离构建列表。每项只运行该模块对应的隔离用例；在没有主体与兄弟源码的夹具内构建，并运行自身行为测试。实际包消费放进就近的 `scripts/tests/<模块名>-package.test.mjs`，沿用现有打包夹具，不复制一套打包系统。

以第一项为例，在库隔离工作树执行：

```sh
node scripts/build.mjs llm-text
node --test src/llm-text/tests/*.test.mjs scripts/tests/exports.test.mjs
node --test --test-name-pattern='llm-text compiles' scripts/tests/build.test.mjs
node --test scripts/tests/llm-text-package.test.mjs
```

后两项将模块名替换为 `bounded-map`、`response-text`。上述新增测试文件尚未存在，由对应步骤实现。测试入口在报告中写实际文件、命令与结果，不把本计划中的命令算作运行过。

打包夹具须先确保整个包会交付的导出产物已构建且未过期；只构建一个新模块后拿残缺 `dist` 打包不可取。按现有构建器补齐需要的产物，然后在临时目录打包和安装，从 `wanxiangli/<入口>` 消费，隔绝开发树和 `NODE_PATH` 的兜底。临时归档不入 Git。按现有 Node／Bun 支持范围运行新模块消费者，记录实际运行时；没有运行的环境就写未运行。

### 2.3 并列目录与固定候选

长期开发目录继续并列。当前程序仍使用 submodule，目录目标和已实现接线必须分别说清楚。本轮不顺带设计全新的取依赖系统，也不改成浮动的 `file:../wanxiangli`。

主体隔离工作树中的 `wanxiangli/` 是过渡方案所需的候选依赖检出，不是把并列库仓迁回主体。先取得库候选的明确 SHA，再使这个检出与 gitlink 固定到同一 SHA。正式主体交付前，库 SHA 必须在协作者可取得的远端；本地配对试验可以先用已提交候选，但不能据此报告可交付。

具体顺序：

1. 库侧完成相关构建、测试并提交，得到候选 SHA。检查相对前一项候选的差异，仅含本项及明确必要的支撑改动。
2. 在主体隔离树初始化现有 submodule，取得并检出该明确候选。不得用“更新到最新分支”代替选定 SHA，不覆盖有修改的依赖检出。
3. 保留 `file:wanxiangli`，按现有 npm 配置刷新锁文件（`npm install --package-lock-only --ignore-scripts`），再 `npm ci`。若 lock 出现不相关依赖变动，先查原因，不把它们混入提交。
4. 将候选 gitlink 暂存，接入公开入口，完成该项主体构建与相关测试。提交前检查以 index 中的 gitlink 为准；主体提交记录 gitlink 与必要锁变化。
5. 库候选先成为可取得的提交，主体再交付引用该候选的提交；最终报告写两仓 SHA、相关命令红绿和未完成部分。沿用现有 PR／提交说明，不再建一套状态账册。

### 2.4 避免测试与主体各用一份库

历史硬编码 `0.5.2` 的 011 内容已不在当前文件中，但当前 [distribution/011](../requirements/distribution/tests/011.test.mjs) 只检查 gitlink 格式、安装位置和版本等，还没有直接断言“承诺接入的候选 SHA = gitlink SHA = 依赖检出 HEAD”。不能把它现有通过解释成候选一致性已全部覆盖。

第一项施工时，在现有 `scripts/wanxiangli-source.mjs`、distribution/011 或 `scripts/verify-package.mjs` 的合适位置补最小检查，后两项复用，不新增治理框架：

- 集成执行入口使用拟新增的 `WANXIANGLI_EXPECTED_SHA` 接受本次预先选定的候选 SHA；值来自本项库交付，不能通过读取当前安装结果反向生成“目标”。011 与 verify-package 复用同一个候选核对函数；普通开发未传目标时仍核对 gitlink 与检出一致，但不能据此宣称完成本项候选交付。
- 核对预定 SHA、主体暂存／提交的 gitlink、库检出 HEAD 一致；不接受改过源码的同一 HEAD。提交前用 index 的 gitlink，提交后用提交里的 gitlink。
- 声明、lock、实际 `node_modules/wanxiangli` 指向该候选；新增入口从主体安装位置解析，不能另用旁边开发仓的产物。
- 实际主体打包后，在隔离安装中运行新增入口与主体有关路径；以现有打包流程比较被捆绑库的文件内容／摘要与该候选的本次构建产物。版本字符串相等不足以代替内容一致。
- 给这一检查补一个“预期候选错误而版本字符串未变”的失败用例。缺少入口、旧产物或未运行必须显式失败或记未完成，不能转为成功。

主体每项完成业务接线后执行现有构建，再跑该项列出的定向用例，以及因依赖变化受影响的发行检查。先将下例的占位文本换成本项已提交、已选定的完整库 SHA：

```sh
node scripts/build.mjs
export WANXIANGLI_EXPECTED_SHA='<本项选定的完整库 SHA>'
TESTS_MJS_FILES='requirements/distribution/tests/011.test.mjs' node requirements/verification-system/tests/run.mjs
node scripts/verify-package.mjs
```

上述候选环境变量是待实现接口，当前脚本尚不读取它，不能现在仅设置变量就声称已核对。实现时同步更新现有入口说明；格式错误的 SHA 也必须拒绝。若任务进一步包含正式发行，继续遵守已有发行入口的要求，不以定向开发测试代替发行步骤。

当前 `scripts/verify.mjs` 的 focused 路径把 `TESTS_MJS_FILES` 交给 `getTestEnv`，后者又移除此变量；本计划因此直接使用 runner 的显式文件列表，避免误跑全量。这个发现不扩成另一个修复工作包。

## 4. 第二项：有界异步映射

### 目标与边界

公开入口拟为 `wanxiangli/bounded-map`。从 [Parallel.fs](../src/Wanxiangshu/Foundation/Parallel.fs) 迁走每次调用独有的等待队列、许可和结果排序；主体保留搜索策略、关键词数量、失败降级和角色权限。

拟公开接口：

```ts
export function mapBounded<T, U>(
  maxConcurrency: number,
  action: (item: T, signal: AbortSignal) => Promise<U>,
  items: readonly T[],
  signal?: AbortSignal,
): Promise<U[]>;
```

采用平台 `AbortSignal` 是公共 JS 边界的设计选择，不是现有 F# CancellationToken 已天然等价。调用方提供时将同一个 signal 传给 action；省略时本次调用使用一个未取消的 signal。限额为正的安全整数，非法输入在启动任务前拒绝。数组内容在调用时取快照，结果按输入顺序返回。

当前真实使用方是 [WarmStart/Runtime.fs](../src/Wanxiangshu/Repository/Investigation/WarmStart/Runtime.fs) 的 `collectAtWorkspace`，传入 `CancellationToken.None`。此处可以直接省略 signal，不把 Fable 私有 token 结构变成库 API。库以标准控制器覆盖取消契约。

### 必须先固定的异步语义

- 每次调用独有并发上限；并发两次调用不会共享一个全局 semaphore。
- 入队前和拿到许可后、执行 action 前检查取消。已启动任务是否停止由 action 自己响应 signal；库不强杀它。
- 排队期间取消，当前实现要等拿到许可才观察到；本轮不增加“立即唤醒所有等待者”的新承诺。
- action 成功或失败都释放许可。返回值沿输入排序，不沿结束时间排序。
- 当前使用 `Promise.all`，首个拒绝会使总调用提前拒绝，其他已启动及排队任务仍可能继续。错误返回不等于全部副作用已经结束；本轮不改成等待排空、自动取消兄弟任务或重试。
- 不把领域的预算、搜索降级或 provider 生命周期放入映射器。action 是本项要处理的工作函数，不是把其他领域对象的协作流程藏进回调。

### 施工步骤

1. 选出 `structured-workflow/tests/010.test.mjs` 中 bounded map 的行为用例，迁入库并用 AbortController 改写 token 夹具；同文件的 reconcile scheduler 用例继续留在主体。
2. 在 `src/bounded-map/` 实现 `BoundedMap.fs`、工程、声明与测试。内部对象拥有许可与队列；外部只能提交映射请求，不可修改许可状态。注册入口并完成独立构建、实际安装消费。
3. 不搬整个 `Parallel.fs`：其中 `Defer.defer` 负责微任务延迟，`ChatExecutionJournal` 和 `Acceptance` 仍在使用。将它原样留在主体单独的 `Foundation/Defer.fs/.fsi`，不改变调度时点。

5. 删除主体 `Parallel.fs/.fsi`、`ParallelSurface.fs/.fsi` 的旧算法与测试 token Surface。更新 `compile-order.txt`、`Wanxiangshu.Owner.intra-participant-parallelism.foundation-parallel.fsproj`，让 Defer 仍有且只有一个编译归属；若导入直接放在 Runtime 内，不另建空转发工程。

### 定向测试
