## 修订（2026-10-10，clean-build 交付链修复）

- 触发：`verify:release` 在 build 阶段因缺 `dist/Execution/Session/LoopDetectorEnvelope.js` 失败。`--clean` 先清空 dist 且没有 staged backup，旧 `verifyArtifacts` 的 staged-backup 恢复分支救不回产物；手动 derive 写入 dist 后也会在 full rebuild 的 staged swap 中被吞掉。
- 裁决（Manager）：采用选项 B「产物入库 + 构建复制」。CI 与干净工作树必须能自举跑 `verify:release`；「手动更新」落在更新入库产物上，而不是要求 clean 前先跑 derive。
- 实现：
  1. 入库位置 `resources/degeneration-guard/envelope/LoopDetectorEnvelope.js`；路径常量集中在 `scripts/lib/loop-detector-envelope-paths.mjs`。
  2. `scripts/build.mjs · materializeLoopDetectorEnvelope` 把入库产物原样复制到 `dist/Execution/Session/LoopDetectorEnvelope.js`；删除 staged-backup 恢复分支；入库产物缺失时构建失败并提示 `node scripts/derive-envelope.mjs`。
  3. `scripts/lib/derive-loop-detector-envelope.mjs · writeLoopDetectorEnvelopeArtifact` 写盘到入库位置；产物首行注释携带 generated marker（`auto-generated`/`do not edit`），selector 据此把入库产物排除出语料，避免自引用。
  4. 保留「不自动派生、不检查是否改变」两个决定；dist 的 import 目标与 `package.json imports` 不变。
- 剩余边界：验证由 DevOps 执行（clean build 后 envelope 就位、`npm run verify:release` 走到后续步骤）；derive 前后数值对比未在此记录。
