**保持不变的地方。**

- append 的拒绝顺序仍是 ordinal、callId、placement；`int64` 用 bigint 跨边界，不能经 Number 丢精度。
- 上一条只适用于 durable History。当前 `PairGuidanceMemoryStore.fs:97` 的 append 只提取字段后 `list.Add`，不拒绝非顺序 ordinal、重复 callId 或重复 placement；`nextOrdinal` 取最后一项 ordinal + 1，不取最大值。memory 路径原样保留这些行为，不能为了代码复用引入 durable 校验。需要时同域对象共享转换，不能强迫两个契约合一。
- 现有两套 gap key 分别是 History 索引用的 `s` / `b:` / `a:`，以及 occurrence 占位查询用的 `Start` / `Before:` / `After:`。它们用途不同，不合并成一个“规范键”；现有事实里的 TranscriptGap 序列化、地址和 markerText 字节不改。库接收各自已有的不透明键，不把新键回写历史事实，也不新增迁移。

- render 失败不得追加；append 失败不得向调用者返回含新 occurrence 的 wire。现有异常拒绝与普通 Result 错误保留各自出口。

- 本项不顺手删除原有 orphan 检查，也不扩充它；是否删除属于纠偏的另项决定。配对提示不进入 XTrace 的现有分界不变，已标 TODO 的直接捕获问题不在本项修复。

## 轨迹的持久捕获过程（扩充 trace，排在配对提示之后）

**用户得到什么。** 原始任务、实际看到的文本/工具材料和最终输出进入同一轨迹；相同观测重入时不重复追加，失败时已保存前缀仍可恢复。上一轮 TraceHistory 只收拢历史，不等于这段捕获过程已经迁完。

**实际起点。** `src/Wanxiangshu/Context/Trace/Capture.fs` 约 1135 行，当前同时包含宿主 observation 解码和中立的 Blob→Journal 捕获协作。真实调用包括 `OpenCode/Plugin/PluginTransforms.fs` 的捕获与 opening 路径、`Execution/Delegation/Fork/Host/Agent.fs` 的 child opening、`Execution/Delegation/SyncDelegate/Runtime.fs` 的 opening/terminal、`Execution/Fission/Launch.fs` 的 startup，以及 `Context/Trace/TerminalTracePort.fs`。不能只替换 SemanticTraceSurface 的测试入口。

**拟定边界。** 扩现有 `wanxiangli/trace`，增加 `TraceCapture` 合作对象，组合现有 TraceHistory、Blob 写入与事实提交；拥有一轮捕获的去重索引、cursor 分配、按会话串行及前后 receipt 的产生。持久权威仍来自 Journal 返回的历史，不在对象里存第二份长期 Current。串行复用 `wanxiangli/keyed-serial`，不再造捕获队列模块。

候选操作为 `captureOpening`、`captureParts`、`captureTerminalText`、`captureTerminalReference` 与读当前历史；形状以当前行为反推。Blob 与 Journal 以窄协议交入，事实转换在主体；不得接收 AgentJournal 的全部表面。part 输入包含文本语义、已解码的不透明 observation identity、相关不透明匹配键及原样 metadata。Identity 的生成与“这是不是重试注入”“宿主 part 的哪个字段可靠”由外层解释。

**边界开工条件。** `Capture.fs` 的稳定身份算法目前解释 `g:/msg:/host-part:`、HostToolPartId 与旧 positional 格式。先把这些规则归入万象通的 observation 适配，并保持字节格式；库只执行已有匹配关系，不认识 OpenCode、ProviderRetryAttempt 或宿主字段名。若为了隐藏这些规则反而设计出每一步都回调宿主的空壳 TraceCapture，应停在调查阶段，保留本项为后排，不能为了补足数量硬迁。

**施工顺序。**

1. 逐段给 Capture.fs 定位：宿主 observation→中立材料；已有历史→本轮去重/游标；写 Blob→提交 fact→读取更新后历史。先明确稳定模式和位置模式的差别，不把两条硬合成相同行为。
2. 将宿主身份、retry 行抑制、reanchor generation 取得、SessionMessage/ToolParts 解码留适配；保持现有 `g:` provenance 原字符串与 metadata。用现有输入示例确认可形成中立 capture batch。
3. 在 trace 内实现完整捕获协作，组合 History 与 KeyedSerial。Opening、parts、terminal 用同一组参与者；不为 terminal 或去重索引另开入口。写入错误携带原始错误，宿主映射原有 Refused/StorageAppendFailed/StorageFailed。
4. 切 `Capture.fs` 的核心协作，让各 WithReceipt 入口进入新对象。保持串行 key 是 sessionId 的现状；不要改成每 Journal 对象一把锁导致同 session 并行分配 cursor。
5. 切上述 Plugin、Fork、SyncDelegate、Fission、TerminalTracePort 真调用。保留宿主 terminal 形成与 NotifyTerminal 逻辑，不把 TerminalReporter 整段塞进 trace。
6. 删除旧 captures 单例、游标分配/索引和 Blob→fact 提交循环；主体留 observation/事实/错误转换。TraceHistory 读区间与材料还原不重写；审计不动。
7. 运行指定差分并实际 reopen。特别检查没有因为 JS Promise 或 F# Task 桥改变首次取快照/分配 cursor 的时机。

**保持不变的地方。**

- 无 Journal 时返回原空 receipt 与 Current=None；不因此启动新的内存审计或临时持久化。
- opening 只在尚无 opening 且 assignment 非空白时写入；同 providerRun、同 terminal digest 重入是 no-op；不同 terminal 仍交既有 fold 决定，不能增加覆盖或恢复策略。
- 一批先读快照再串行追加，Blob 先于对应事实。第 k 项失败时前 k−1 项可能已经提交；不能把批量改成原子事务或失败后重发整批。
- 当前 stable 索引以批次开始的历史建立，不能顺手新增批内去重，从而悄悄改变行为。
- 稳定物理 part identity 优先；兼容旧 positional 项时同时比较 run/kind/tool/call/host-part/digest。缺少 run/call 的旧记录仍能参与匹配；禁止用空字符串统一未知身份。
- 普通观测的稳定身份资格不足会走现有 positional 回退；直接要求 stable 的入口仍拒绝缺失、空白、重复 IDs。不能在拆分时统一成严格拒绝或静默回退。
- typed retry observation 保留位置与身份但贡献空 parts；看起来像 retry 的普通文本仍原样保留。此判断留外层，不让核猜文字。
- 稳定分支 Blob Result 错误与位置分支抛异常的既有区别，最终 WithReceipt 分类和消息须保留；JournalAppendFailure 原对象不能只剩字符串。
- 最终输出的角色/有效交付/空正文判定以及 failed notification 属于 TerminalReporter，保持原逻辑，不在本项调整。

## OpenCode 请求延迟看护：计时、中断与续行回执的一个寿命

**归属：万象通，不迁入 degeneration 核。** 核已有 `requestLatencyDetector` 统计 owner；外层约 629 行 `OpenCode/Host/LatencyWatchdog.fs` 所承接的“Abort 停整个会话循环”是 OpenCode 协议事实，把 Abort 改名成中立 callback 不能使之变成中立核。
