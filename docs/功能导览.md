# 万象术功能导览

万象术解决的不是“怎样再叫来一个模型”，而是几位智能体怎样在同一个工程里把事做完：分工不混，事情有据，失败能接，交差有人认，最后落在同一份代码上。

它以 OpenCode 插件落地。Host 提供会话、模型调用和公开 Hook；万象术在上面管理身份、委托、工作、上下文、执行与恢复。它不修改 Host 源码，也不把提示词里的劝告当作运行时权限。

本文按工作中的用途盘点独特机制，不按源码目录逐个报名字。“独特”指本仓有明确设计与实现归属的能力，不表示已经证明别的产品没有。盘点依据为 2026-10-20 的工作区，包含正在修改的源码与规范；这是功能导览，不是该工作区的测试证书。正式含义归各包 WHAT，运行缺证归 [GAP 台账](../requirements/GAP.md)。

## 一、先分清谁有权做什么

### 分工不是换一段角色提示词

- **Orchestrator** 开辟和接续独立的 Manager 道路，判断互补成果怎样集成、竞争方案怎样取舍，不直接组织源码施工。
- **Manager** 拆任务、派 Engineer、续做固定 DevOps、审看证据并验收。它不亲自改源码、不执行命令，也不能裂变成几个 Manager。评审前有专用只读取证窗口；后续准入由当前工作事实收口，最终收尾另有窄窗口。
- **Engineer** 查本地事实，编写、修改、移动和删除源码及测试。它不能执行真实命令，即使命令看似只读；不能差遣 DevOps，也没有外网浏览职责。
- **DevOps** 真跑命令、构建、测试和进程检查。普通非架构缺陷由它直接修复、补回归、重跑，不必每修一处再申请许可；产品含义、安全政策和架构选择仍交回 Manager。
- **Plan** 写规划底稿，不取得整个仓库的读写权。它借固定 DevOps 调查，经 review 晋级，再交付规划或接力。
- **Advisor** 只读调用者交来的那份完整视图，给第二意见，不持有工具。**Bookkeeper** 只整理和维护指定案例，不调查仓库。两者都不能替外层任务宣布完成。

身份分成 Role、Persona 和物理执行绑定。换模型不等于换角色，也不抹掉原先的职责与承诺。一个物理会话可以承载先后不同的逻辑工作，但旧运行没有精确关闭，就不能借同一个会话名安装新身份。

权限从同一份能力事实投影到工具定义和执行门禁。没有权限的方法，不应出现在生成基类、描述和示例里；绕过描述直接调用，也会被运行入口拒绝。模型档位不扩权，历史旧角色也不会在恢复时自动升级成 Engineer。

依据：[身份](../requirements/participant-identity/WHAT.md)、[职位](../requirements/office-capability/WHAT.md)、[权限](../requirements/capability-enforcement/WHAT.md)、[会话分类](../requirements/session-ontology/WHAT.md)。实现入口：`src/Wanxiangshu/Foundation/OfficeCapability.fs`。

## 二、委托可以并行，责任不能散掉

### 新建、续做、收取结果各有含义

Orchestrator 用 commission 委任 Manager；Manager 用 fork 新建 Engineer，用 resume 续做已有工作。每条道路绑定唯一的 DevOps，稳定名称为 `devops`，不能通过再 fork 一个操作员绕开既有归属。

派发成功只证明对方确切承接，不证明任务做完。传输层说“请求已提交”还不够；接收未知时保留原请求身份，明确报告不确定，不假装失败后另发一遍。

复用同一个人不把两次工作混成一次。新的 charge 有自己的因果完成边界；旧回合迟到的完成通知不能结算新工作。忙碌中的 resume 可作为原工作追加指导，进入下一次尚未准备的请求，不抢断当前输出或工具，也不悄悄变成新 assignment。

**join 收已经到达的后果，horizon 看仍在远处的事物。** horizon 是调用时的一次快照，不是后台监控；它呈现可见伙伴、最新交付和仍在场的终端。具备估算与会话起点时，还给出已用和预计剩余回合、时间，帮助决定下一步。估算不构成期限或完成证据。

用户新输入可以打断 join 等待，但不自动取消 child，不抢断当前模型输出或其他工具。Manager 听取后再决定是否调整任务。

### DAG 把依赖写明，不让到达顺序冒充依赖

编程面的 `dag` 接受节点、任务和依赖，调度就绪工作，把上游交付带给下游。节点失败通过 park 交回判断，可重试、跳过、给出替代结果或中止；不是把失败藏进空结果继续跑。它只是现有委托能力的组合，不会给调用者新增角色权限。

同步受托调用在逻辑上保留 owner，物理上挂在家族根下，不堆出孙会话。批次取自 Host 的真实调用集合，不凭回调先后猜成员。

依据：[委托](../requirements/delegation/WHAT.md)、[视界](../requirements/participant-horizon/WHAT.md)、[编程面委托](../requirements/repository-programming/WHAT.md)。实现目录：`src/Wanxiangshu/Execution/Delegation/`。

## 三、一个 Engineer 可以有几条当下

Fission 与 fork 不同。fork 多了一位独立受托人；Fission 是同一位 Engineer 同时沿几条 lane 工作，身份、权力和最终责任没有分家。

- 只允许符合资格的 Engineer 子会话使用；根会话、其他角色和已有活跃裂变组不能再裂变。
- lane 以同级物理会话展开，全部准入后才替换旧执行；创建失败不能只留下半组有效 lane。
- 裂变前已有的未决后果向各 lane 确定性交付；裂变后新任务保持发起 lane 的消费亲和。
- 记录以 lane index 为 key 汇聚，同 key 同内容幂等，冲突拒绝，不按谁先回来拼接。
- 收敛按固定索引顺序环行，最终接管者明确。父级只收到一次整合后的完成，某条 lane 的局部交付不能冒充 owner 的最终交付。

它适合确实独立的调查或实现切片，不适合让几条 lane 抢改同一个文件。当前全程身份、恢复、真实终结等证明仍有缺口，不能把局部测试当成完整裂变链已验收。

依据：[同一参与者并行](../requirements/intra-participant-parallelism/WHAT.md)。实现：`src/Wanxiangshu/Execution/Fission/`。

## 四、用程序操作仓库，而不是拼一串零碎 RPC

### 按角色生成的 JavaScript 工作面

`todowrite-for-<role>` 的名字沿用宿主入口，实际不是一张待办表。模型提交一个继承 `JsProgram`、实现 `async run()` 的类，组合自己获准使用的文件、委托、执行和生命周期能力。

- `cat` 读取严格 UTF-8 快照；`stat` 区分不存在与读取故障。
- `ls` 列一层可见目录，遵守 ignore；`rg(argv)` 负责路径枚举和内容搜索，返回结构化数据。未命中不是执行失败。
- `whereAll` 返回全部规范化精确匹配；`where` 只在唯一匹配时直接返回原文 span。
- `write`、`mkdir`、`mv`、`rm` 承担写、建、移、删。文件路径、符号链接、编码和读后改写的冲突由宿主边界检查。

局部修改用“读快照 → 定位 → 切片重组 → 一次写回”。where 零匹配或多匹配时不猜一个位置，而是带候选、近邻和完整程序执行点挂起；unpark 注入选定值，从原 await 继续。

仓库规范把写入定义为 **As-Is 逐笔落盘**：单笔原子，跨笔不保证回滚，后续失败不能抹掉已经发生的文件效果。因此先在内存构造目标、检查便宜不变量，再写；不能靠最后 throw 把它当成多文件撤销按钮。调用结果应如实报告已经落盘的路径。

沙箱不因会写 JavaScript 就获得环境变量、任意进程或网络权限。成员由能力生成，Manager 没有写和执行，Engineer 没有真实执行；Plan 只能访问自己的 `PLAN_PATH` 底稿。

### 挂起不是重跑

`park(payload)` 保留同一进程内的现场，返回 handle、载荷和执行点。unpark 继续原调用；abandon 消费 handle，并给程序的 finally 清理机会。同一个 handle 只能消费一次，跨 owner 不能随意恢复或放弃；并发现场有上限，会话关闭有清理路径。

这使“先机械处理，遇到语义选择再交回来”成为普通程序结构。它不是跨进程检查点；重启不能复活原 JavaScript 调用栈。

依据：[仓库编程](../requirements/repository-programming/WHAT.md)。实现：`src/Wanxiangshu/Repository/Programming/Js/`；底层能力通过 `wanxiangli` 公开入口消费。

## 五、真实执行有出口，也有看守

DevOps 的执行面是 `this.call(class extends this.Callable { ... })`。模型写工程语义，宿主掌握循环、时间片、进程退出和最终收束。

- `next` 发前台命令、启动具名后台、发送输入或信号、等待端口，工作结束返回 null。
- `watch` 读取本片 stdout/stderr、后台状态和剩余时间，继续、否决或挂起；不是只在命令结束后看看尾巴。
- `onExit` 接收真实退出码与有界输出，决定推进、重试或留下失败。
- 必填有限 `maxDuration`。执行前的 `sanity` 用两个 thunk 展示“正常能结束”和“异常能否决”，没有出口的剧本先挂起，不让它无脑重跑到总超时。
- 同一次 call 可管理服务、REPL、测试等多个真实进程；结束时收束所属后台，不留无人负责的运行体。

命令是动作，输出和退出是观察。发出 signal 不等于已退出，超时也不能编造成正常完成。call 的每路日志有界保留头尾，并报告截断与实际字节数；没有另叫一个模型替日志蒸馏。长输出可能丢失中段，不能据保留片段声称审过全日志。

进程体系还管理大输出资源的互斥和可取消排队。等待时间是购买一次观察的上限，不是进程必定需要这么久的预测。

依据：[进程执行](../requirements/process-execution/WHAT.md)、[Callable](../requirements/repository-programming/WHAT.md)。实现：`src/Wanxiangshu/Process/`。

## 六、交差要有见证，不是一句“做完了”

承担任务的角色不能靠空输出或进度小结解除义务；未走完的账本仍在 horizon 上看得见。用户取消、已完成、显式等待和基础设施故障分别处理，不混成无限重试。

Engineer 与 DevOps 以**有正文、无未决工具调用的自然终态**交回本轮 assistant 散文。程序里的普通 return 只结束该次调用，不等于会话已完成。任何角色如果没有正文也没有工具调用便自然停止，宿主继续 nudge，当前不设上限。

Manager 与 Plan 仅通过 `review` 提交义务账并结算当前任期：清空台账时接力，接任首次空账晋级，收尾时阻塞已解除方能结案。生命周期判断绑定真实任期与请求，不允许旧回执推进后任。

Advisor 和 Bookkeeper 属于内部末梢：顾问席以散文回答并随停机返回，案例事务沿专用提交收敛，都不能用内部回答代替外层任务交付。

ask 和 Fission 接管等长程连续性路径仍在补证。当前实现可定位，不代表全角色真实 Host 链已经闭合。详见[GAP 台账](../requirements/GAP.md)。

依据：[工作连续性](../requirements/work/WHAT.md)、[交付与围栏](../requirements/repository-programming/WHAT.md)。实现：`src/Wanxiangshu/Composition/Turn/OrdinaryTurnWorkflow.fs`、`src/Wanxiangshu/Repository/Programming/Js/DeliveredValues.fs`。

## 七、规划有底稿、有晋级，也能接棒

Plan 围绕一份持久 Markdown 底稿 P 工作，不把底稿全文每轮塞入提示。阶段依次是 S1 事实与取舍、S2 理解与路径、S3 流程与伪代码；不同阶段有对应的方法资源。

- 每任通过 review 维护义务账，首次 review 后才按门禁开放写入；findings 为可逐项删除的义务。清空台账先接力，接任首次空账才晋级。
- review 清空台账后原任退休，新任沿用当前里程碑；只有接任者第一次空账评审通过才能推进。
- S3 获权后交付规划，进入 post-S3，先等待用户，不把规划就绪冒充执行已经承接。
- 用户显式要求执行时，再启动无 parent 的 Manager S4 会话，传入精确的 P 全文。每次启动独立记账，先预留、绑定真实执行会话，再发送；结果未知只核对原 operation，不另起一份。
- 用户继续修改规划可重开新任，旧任不复活；只要求执行产物，不应误触发规划重开。

只有 S1 的 Plan 可通过 `this.ask(question)` 向用户询问必要信息。询问登记后暂停本次尝试，等待从持久问题事实派生；内部 continuation 和旧输入不能充当答复。新真实用户输入接续同一目标，重复与迟到回执不能中断新一轮。Manager 没有 ask 权限。

Manager 的执行和收尾依实际 review 义务账推进：清空台账但仍有合法工作阻塞时不得结案；确切结案与接力由工作生命周期事实裁决。真实子任务、进程、工具和租约是终局 blocker；接力保留固定 DevOps 及其已受理任务，不因 Manager 换任把工作孤儿化。

Work 生命周期由独立 `wanxiangli` 的 Work / DurableWork / SQLite journal 管理，同一事实不再由旧 EventStore 重复投影。规划、执行启动与用户等待的组合证据仍应看当前专项记录。

依据：[Work 与 Plan](../requirements/work/WHAT.md)。实现：`src/Wanxiangshu/Mission/`。

## 八、上下文边界由当事人划定，宿主不替它猜重要性

### resetScope 是唯一的上下文边界

`resetScope(oldScopeVerboseVerbatimExperience?, newScopeObjective, newScopeTurnBudget)` 删除上一次 `resetScope`（或会话开始）到本次调用之间的全部内容，只保留用户消息与既往的 reset 成对记录；调用之后的内容属于新 scope。`newScopeObjective` 写清这一段要闭环到什么状态，`newScopeTurnBudget` 是这一段的回合数估计；可选的 `oldScopeVerboseVerbatimExperience` 把下一段仍需逐字使用的原文（函数签名、报错栈、精确行号）交接出去，不留“靠记忆重写”的余地。

边界只在调用点生效：它同时是执行屏障与上下文回收，不是后台悄悄改写历史。屏障之前发出的工具调用先执行、其上下文随后被删除；屏障之后才进入新 scope。

### turnBudget 是倒计时，不是硬闸

每次 reset 之后，工具结果尾部带一行 `[Remaining turnBudget: N]`。归零时只给一条弱提醒，明写不必为此中断、暂停或放弃手上的活，到自然边界再 reset 即可；预算耗尽不封锁任何动作，也不构成失败。会话开始同样有一条提醒，要求先为第一个细粒度任务块估算预算、再立即 reset。宿主披露实际内容计量、缓存计费和 provider 声明的 context limit，但不据此估算剩余容量、预测溢出，也不自动压缩。

### 三个方向传递的都是完整的 post-scope 视图

不再由模型挑材料：谁说话，就把说话之后自己那份面向模型的完整视图原样交出去。

- 父→子（fork、resume、commission、devops 咨询、dag、advisor）：指令散文以 `#` 注释头传送，发送方本次 scope 之后的完整 LLM 视图作为 TOML `[[context]]` 表随同发出；任务本身在 `charge` 或 `intent` 中表达一次。
- 子→父：Engineer 与 DevOps 自然停机即为交付，宿主把子方末轮 assistant 散文作为 TOML `#` 注释返回，父方 `join` 收到的就是这一份；不再有 `[[session]]` 表，也不返回子方完整视图。
- 顾问席：一次咨询等同于父方问子方一个问题，同样带发送方的完整 post-scope 视图，交回的是顾问末轮散文，返回 `{ ok, advice }`。

传递材料保持结构化，最终排版为可读的 TOML；不会把 TOML 再挤进字符串字段。

### 前缀稳定与原始历史分开

同一语义 epoch 内，保护区的历史字节、system 和工具面保持稳定。`resetScope` 落一条 `ScopeReanchored` 事实推进前缀 epoch，任期交接另有明确的重锚事实；两者都不靠“感觉快满了”换 epoch。辅助标记原位原字节重放，旧 elapsed 不在每轮重算。

XTrace 保存 append-only 的 Opening、语义部件和 terminal，按因果游标切片，区分 provider run 与 invocation。请求里的摘要不改写原始历史；但原始存储仍受 writer retention 范围限制，不是无限期档案。

`assume(assumption)` 只是钉住已经形成的判断，帮助停止重复思索；不求证、不维护持久画板、不写待办，也不证明完成。

依据：[上下文](../requirements/context-compression/WHAT.md)、[前缀](../requirements/prefix-stability/WHAT.md)、[语义轨迹](../requirements/semantic-trace/WHAT.md)、[义务台账](../requirements/obligation-ledger/WHAT.md)。实现：`src/Wanxiangshu/Context/Scope/`、`src/Wanxiangshu/OpenCode/Tools/ResetScopeTool.fs`、`src/Wanxiangshu/Context/Prefix/`。

## 九、模型调度看真实占用，不看角色自称

模型选择唯一来自用户的 `~/.config/opencode/wanxiangshu.mjs`，协议 2 的输入为 role、真实运行目标 multiset 与接续偏好 previous。缺配置时创建推荐模板，已有配置不覆盖；非法导出拒绝，不另拿环境变量或 Host 默认模型兜底。

- scheduler 返回 null 是等容量，不是 provider 失败；等待有界、事件驱动。
- durable Accepted 在先，获取精确容量在后，最后才投影到 Host；发送意图不提前占槽。
- 租约精确绑定物理输入、角色、参与者、目标和 fence。旧回调不能释放新消息的容量，同一 physical 的重放不能另选模型。
- provider step 与整个工作生命周期分开。工具开始前交还可借用的 step credit，防止父工具等待 child、child 又等父模型容量的死锁。
- 借用须有显式 lender，不能按父子关系猜信用；归还、召回和排队各有 owner。
- 固定 DevOps 的道路绑定另受持久目标约束，不能借 resume 换坐骑。

调度模板不是模型能力排行榜，也不保证其中每个角色池都已在当前配置中完备。当前随包模板的注释与实际 pools 存在差异：注释列出 Plan、Advisor，pools 未列这两个角色。因此不把“支持角色身份”写成“默认模型配置已保证可运行”。

依据：[模型路由](../requirements/execution-model-routing/WHAT.md)。实现：`src/Wanxiangshu/OpenCode/Host/ModelRoutingSurface.fs`；模板：`resources/wanxiangshu.mjs`。

## 十、失败只归一家恢复

普通 provider 恢复有连续失败预算，保持角色、任务和原 authority。当前策略是某个目标首次失败保留原目标原样重试；确切重试再次失败才在本进程驱逐该 provider，换候选后同理。业务主请求成功清零连续失败；修复回合不能冒充主工作成功。

Host 重试配置置零，但配置不证明所有 Host 内层实际请求都已唯一，兼容性仍需真实 canary。插件也不能承诺拦住 Host 原生弹窗；当前合同明确外部插件的呈现能力边界，耗尽后只发自己的唯一终态呈现。

失败策略在可信边界分成拒绝、取消、容量不足、provider 故障、提交未知等封闭类别。不解析 stderr 或错误散文决定重试；需要 fatal 的路径也先结算已发生事实和资源，不能先杀进程再指望 finally 补账。

依据：[失败策略](../requirements/execution-failure-policy/WHAT.md)、[恢复](../requirements/provider-attempt-recovery/WHAT.md)、[Host 恢复所有权](../requirements/host-provider-failure-ownership/WHAT.md)。

## 十一、重启保留事实，不复活旧进程

重启不恢复 callback、租约、park 栈或命令执行位置。系统用 durable facts 与 Host/Git 的可信物理观察重新判断，进入普通合法流程，不恢复隐藏程序计数器。

- 中断的工具保持中断，不自动重放、补写完成或假定成功。
- 上一 runtime 遗留活跃 child run 在归位时作废，不制造一份可 join 的虚假交付；作废结清父方的未解除义务——join 以 `voided` 状态报告一次后该工作退役，重启不重复报告。显式续做使用原道路身份。
- 本地注册表只是当前进程缓存。child、handle、lane 的存在与归属从 durable 投影按需解析，不因缓存 miss 宣判“此人不存在”。
- 物理 session 丢失、attempt 中断、逻辑取消是不同事实，不能见 abort 就把整个 child Abandoned。
- 外部效果结局未知先核对；证据不足保持 Waiting、Blocked 或明确 manual，不靠时间经过判成功。

下一次真实用户输入前有一次只读重启说明，不借说明创建新 authority。完整启动链、所有 crash cut 和 started-no-terminal 等恢复形状仍有 GAP，不能把“能重开存储”说成“任意中断都自动续完”。

依据：[崩溃调和](../requirements/crash-reconciliation/WHAT.md)、[消息执行](../requirements/managed-chat-execution/WHAT.md)、[会话生命周期](../requirements/managed-session-lifecycle/WHAT.md)。

## 十二、事实账本留因果，不按钟表挑赢家

### 同机状态与源码分开

运行数据统一位于主工作树的 `.Herdchestra/`，linked worktree 共用；不同仓库和 submodule 保持隔离。通用事件在 `wanxiangshu/events/`，Work 等独立职责用各自 SQLite。运行时不写 Git objects、refs、hooks 或 SSH wrapper，不同步远端运行账，不读取旧 `.git/wanxiang*` 作为恢复来源。当前只承诺同机持久化。

### 完整行提交与确定性重放

通用事件以 canonical JSON + LF 追加，同身份必须同字节；大载荷以哈希引用内嵌同一行，自包含校验。每进程一个 writer，物理上按 64 MiB 上限滚段，逻辑流连续；新进程不能接着旧 writer 写。

先落盘，再推进 Current。唯一 canonical Integrator 解释通用事件，各业务注册纯 fold，不自行扫描历史重建第二套状态。损坏行、身份碰撞、内部缺 parent、循环或 payload 哈希不符都 fail-closed，不能跳过坏页。

合法并发保留所有分叉，显式形成 DomainConflict；裁决须认全竞争 heads。合流按因果辈分，不能拿 event id 字典序、revision、墙钟或到达先后来挑赢家。

writer 按最近活动的 UTC 日期整组保留今天与昨天，过期整组退出，不在保留流内挑删单条事件。这个规则不是“恰好 24 小时”，也不是永久保存；时间只参与这类物理留存，不裁决业务真伪。未变化的读取与收敛有缓存短路，缓存不成为权威。

### 外部效果单独记账

请求意图、传输提交、物理接受与完成确认分型。先记 intent 再行动；有请求无确认只说明 Unknown，不说明没发生。PromptDispatcher 用稳定 PromptKey 管幂等，不能靠重发直到撞上成功来消除不确定性，也不虚构 exactly-once。

依据：[持久事件](../requirements/durable-events/WHAT.md)、[收敛](../requirements/durable-convergence/WHAT.md)、[外部效果](../requirements/effect-accounting/WHAT.md)、[消息派发](../requirements/dispatch-protocol/WHAT.md)、[交互权威](../requirements/interaction-authority/WHAT.md)。实现：`src/Wanxiangshu/Persistence/`、`src/Wanxiangshu/Composition/Durable/`。

## 十三、经验可以复用，旧答案不能冒充新证明

Casebook 按逻辑工程工作留案例，不按物理 session 覆盖最后一份答案。它保存任务与答案、来源轨迹、实质访问路径，以及完成时与最近维护时的双基线。

实质访问取自真实执行：读过内容、提交了修改、移删了路径才关联；ls、检索候选、正文提到某文件不算读过它。

`fetch(shelfmark)` 取旧案后一次捕获当前文件状态，计算真实 diff，交给 Bookkeeper 维护。成功同时推进正文和维护基线；失败保留旧案与旧基线，明确维护未完成。不反复读取追逐“绝对最新”，不因文件未变就宣称答案正确。

缓存按事件派生的访问次序做有界 LRU，不靠时间戳裁决知识。未启用 Casebook 的仓库不注入索引与 fetch。全链自动归档、权限、并发等仍有缺证。

仓库调查另有显式关键词 warm-start：只给有仓库证据权的直接消费者低信任定位片段，保持顺序、有界去重、故障不阻断主工作；没有关键词就不擅自搜索。命中提示必须重新核实，零命中不证明不存在。

依据：[经验复用](../requirements/knowledge-reuse/WHAT.md)、[仓库调查](../requirements/repository-investigation/WHAT.md)。实现：`src/Wanxiangshu/Repository/Knowledge/`、`src/Wanxiangshu/Repository/Investigation/`。

## 十四、顾问专席与 Sphinx 是两种不同工具

### 顾问给第二意见，不替你办事

`advisor(intent)` 按调用 session 复用同一专席，一次请求等同于父方问子方一个问题：`intent` 以 `#` 注释传送，调用方本次 scope 之后的完整视图作为 TOML `[[context]]` 一并送出，顾问自己的 law 与它分开装配，不揉成一段。返回 `{ ok, advice }`（顾问末轮散文，不是它的完整视图），席位数与背景都不再靠调用者挑材料；顾问停机即答完，不会被追加提醒。

顾问没有文件、执行或委托工具，它的散文是意见，不是仓库实测，也不改变调用者权限。旧答案不能冒充对本次问题的证明：材料按完整内容识别，不能仅凭编号说“看过了”。当前专席和 view 的接线可见；精确咨询终态、旧答案隔离等补证以 [GAP 台账](../requirements/GAP.md) 为准。

依据：[Advisor](../requirements/advisor/WHAT.md)。实现：`src/Wanxiangshu/Execution/Delegation/Advisor/`。

### Sphinx 管探究，不另造一个指挥角色

Sphinx v2 是独立 MCP stdio 程序，不是 Role，也不是插件里一个同名原生工具。七个协议入口负责 start、next、submit、status、cancel、export 和 goal amend；它们是同一 Runtime/Core 的边界，不是七套独立调度器。

其独特机制包括：

- 原始 GoalSpec 字节保留；模型可建议重述，只有用户授权的 amendment 改目标版本。
- 图统一存储认识关系、工作依赖、计划树和精化状态，语义按 role 区分；认识图可有环，工作依赖必须无环。
- 计划语义估值与 Agenda 的依赖、冲突、资源装箱分开；未估值不冒充零收益。
- work、attempt、fence 分开，结果精确幂等；同一次 ballot 不拆成独立票，迟到重试不增加证据票数。
- 资源消耗与并发容量分账，用量缺失不写零，实际超支如实记。
- 证书按目标、价值空间、scope 和语义模型寻址；经验、模型估计、后验、覆盖率和确定性界分型，不把局部保证升级成外部真理。
- 原始回答接纳与解释应用分成两个可恢复事务，解释失败不再买一次 LLM 回答。
- 保存问法、排列、遮蔽、seed、模型与实际协议值；测量和干预分开，保留原始 ballot，区分 Borda 描述基线与 BTL/tie-aware 拟合。
- traceHash、stateHash、semanticHash 各有对象；重放不联网、不重跑模型。Completed 要有正式答案提交，资源耗尽不叫“认识收敛”。

这部分必须限缩表述：源码和协议内核存在，持久创建、读取等有历史局部证据，但 GAP-219/222 仍保留真实工作提交、改目标、renderer、取消和完整 Host 执行闭环等缺口。不能把数学内核、测试 surface 或七个工具名称的存在说成生产探究全链已经可用。

依据：[Sphinx v2](../requirements/sphinx-v2/WHAT.md)。实现：`src/Wanxiangshu/Sphinx/V2/`。

## 十五、提示、语言与表示也有边界

认知材料分 World、Role、Library、Runtime、Mission：共同法讲通用规矩，角色法讲职责，职位书讲经验，运行说明讲此刻处境，任务讲本次目标。读到一本书不会平白取得它描述的权限。

提示词与工具资源按英文、简体中文成对提供，模板参数集合一致，缺所需语言明确失败，不偷偷回退。当前语言实现与现行 provider-language 合同读取全局偏好，变更影响下一次渲染；部分共同法文字仍写“一生一种语言”，存在文案口径差异，本文不替它造一个会话语言绑定。

合成内容由统一强类型表示层组合，再渲染一次。指令和参考数据分面，TOML 转义与布局只有一个所有者；渲染文本不能被业务反向解析成授权。面向模型的 horizon 尽量只给会改变下一步行动的事实，不暴露隐藏评审编排；编程面的结构化信封与人读工具散文仍须区分。

依据：[认知环境](../requirements/cognitive-environment/WHAT.md)、[语言](../requirements/provider-language/WHAT.md)、[表示](../requirements/provider-projection/WHAT.md)、[动作契约](../requirements/action-affordance/WHAT.md)。实现：`src/Wanxiangshu/Resources/`、`resources/provider/`。

## 十六、让机制可以检查，也可以关掉

等待诊断能回答谁在等、等什么、谁能满足、最后相关进展和怎样结束，并沿依赖找外部前沿、断链或循环。诊断只帮助排障，不授权重试、恢复或业务分支。时钟与 timer 用显式能力注入，纯时序可借虚拟时间重放。

功能消融用注册节点、三态和 DAG：active 正常启用，ablated 零影响关闭，borrowed 只运行明示借用面。profile 与单节点覆盖都经过依赖校验，不靠散落开关拼一个说不清的配置，也不允许重新打开已退役角色。

验证按 **Pure → Temporal → Adapter → 唯一 Long Stroke** 逐级推进。测试须能抓到反例，未运行、TODO、被截断或缺有效汇总都不能算通过。验证输入要绑定固定快照，并拦截运行中改料；挂死看真实因果进展，不拿无关心跳续命。

语义测试经正式 JS-native surface 访问生产实现，不靠 Fable 联合类型序号或内部反射猜行为。requirement 包拥有唯一 WHAT，测试标题锚定条款，证明缺口集中记 GAP，避免另写一份“已全部完成”的平行真相。

依据：[等待](../requirements/causal-wait/WHAT.md)、[时间](../requirements/time-capability/WHAT.md)、[消融](../requirements/feature-ablation/WHAT.md)、[验证](../requirements/verification-system/WHAT.md)、[语义边界](../requirements/js-semantic-surface/WHAT.md)、[规范系统](../requirements/requirement-system/WHAT.md)。

## 十七、代码怎样汇合，产物怎样交出去

独立施工道路使用 worktree，进入共享 ref 走短 Integration Gate：最后核目标、只快进 CAS，不把长评审、修复和 rebase 塞进全局锁。目标前进或源码变化后，旧验证资格不能沿用；几路各自绿，合流后仍要在最终工作树验证。请求准入有 Clean Gate，不自动 stash 用户改动。

源码以 F# 编写、Fable 发射 JavaScript。subsystem 拥有语义，compile shard 只承担隔离与增量编译，不是另一套治理职位。构建按签名与依赖选择影响闭包，合并为一次平坦 Fable 编译；有 no-op、focused、full、clean 和只读 plan，实际 ESM 模块图还要检查链接闭合。

发布物携带 dist、resources、允许的根元数据和明确 bundle 的 wanxiangli。资源按模块位置寻址，不依赖调用目录；真实 npm pack、解包逐字节校验和隔离消费者导入，防止“只有在源码仓库里才装得起来”。wanxiangli 由正式 submodule 源码构建，宿主记录确切 gitlink，不在运行时拉更新，不把临时 tgz 入库。

日常入口是 `npm run format-build-test`；发布入口是 `npm run verify:release`。本文没有运行它们。Long Stroke 的缺口状态以 [GAP 台账](../requirements/GAP.md) 为准，GAP 中另有旧 generation 的成功记录；两者都不能当作本次 dirty 工作区的证书。

依据：[集成](../requirements/change-integration/WHAT.md)、[结构化工作流](../requirements/structured-workflow/WHAT.md)、[发行](../requirements/distribution/WHAT.md)。入口：`scripts/build.mjs`、`scripts/verify.mjs`、`scripts/verify-package.mjs`。

## 当前不能算在功能里的东西

旧文档、注释、历史类型和退役边界仍会出现旧名字，不能据此推断它们仍可用：

- 不提供外网浏览角色或工具，不恢复 Coder、Inspector、Browser、Inquiry、Distiller 的活跃职位。
- 不提供 Predictor、只读投机副本池、Blogger/Chronicle/squash 自动压缩。
- 不提供 jq/canvas 持久认知画板、Concern 邮箱、subscribe/publish/defer/enough 注意力状态机。
- 不把原生 todowrite 当第二份任务真相，不把直接 read/edit/write/glob/grep/patch 或原生 run/PTY 工具当当前文件与执行入口。
- 不提供运行数据的 Git 远端同步、跨机恢复或旧 .git 数据自动迁移。
- 不提供原生 sphinx 工具或旧 epistemic-reasoning 内核的兼容驾驶层。

万象术的功能可以归成一句话：让每个智能体在自己的权限内继续做有用的事，并让事实、责任与结果在并行、失败和换任之后仍然对得上。能否兑现，要由当前代码、当前输入和实际验证回答，不能由这份导论替它回答。
