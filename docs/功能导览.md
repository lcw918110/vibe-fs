# 万象术功能导览

万象术解决的不是“怎样再叫来一个模型”，而是几位智能体怎样在同一个工程里把事做完：分工不混，事情有据，失败能接，交差有人认，最后落在同一份代码上。

它目前以 OpenCode 插件形式落地，正依照纠偏令向三层分工演进：
1. **本仓产品面（wanxiangshu）**：负责提示词、工具资源与顶层组装，逐步减负，最终不保留程序状态。
2. **万象通（wanxiangtong）**：负责宿主（OpenCode 等）怪癖与生命周期 hook 的翻译抹平（外层目录，暂不开独立仓）。
3. **万象理（wanxiangli）**：中立内核，遵循 Smalltalk / Actor 模型，状态自治，不认识任何具体宿主。

本文按总流程中的实际用途介绍核心机制。文档描述的是**目标与现存能力**，若具体代码尚未完全解耦，以文中标注的【程序待改】为准。

---

## 一、分清谁有权做什么

### 角色不是换一段提示词，而是硬性权责边界

- **Orchestrator**：开辟和接续独立的 Manager 道路，判断互补成果怎样集成、竞争方案怎样取舍，不直接组织源码施工。
- **Manager**：拆解任务、派工 Engineer、唤醒并续做固定 DevOps、审验结果。它不亲自改源码、不执行命令。
- **Engineer**：查本地事实，编写、修改、移动和删除源码及测试。它不能执行真实命令（即使看似只读），不能差遣 DevOps，也没有外网浏览职责。
- **DevOps**：真刀真枪跑命令、构建、测试和进程检查。普通非架构缺陷由它直接自修、补测试、重跑，不必每修一处再请示；架构和产品决策交回 Manager。
- **Plan**：编写规划底稿，不取得整个仓库的写权。
- **Advisor**：专席顾问，只读调用者交来的完整视图，给出第二意见，不持有外部工具。
- **Bookkeeper**：整理和维护案例，不调查仓库，不替外层任务宣布完成。

身份分成 Role、Persona 和物理执行绑定。换模型不等于换角色，也不抹掉原先的职责与承诺。

【程序待改】：部分旧代码中仍残留运行时不变量巡检和双向检查员逻辑，后续需清理为单向结构约束。

## 二、委托与并行：责任不能散

### 新建、续做与兵分几路

- **委任与派工**：Orchestrator 委任 Manager；Manager 派工给 Engineer；每条道路绑定唯一的 DevOps。
- **换人不是换马**：同一个逻辑工作可以更换底层模型（ModelTarget），但历史上下文、承诺与责任不变。
- **Fission（同参与者多路并发）**：
  - 只有 Engineer 可以在允许的子会话中发起 Fission。
  - 各路（lane）拥有不同的局部任务或互不重叠的文件写入区域。
  - 各路是同一个 Engineer 的多个当下，不是新代理，共享同一份权限与责任。
  - 必须由发起者统一收敛，合并为一个最终结果交回 Manager，不能各自单独宣布完成。

## 三、文件与编程面：todowrite

### 代码修改是一次性严肃操作，不是盲猜替换

文件系统操作主要通过 `todowrite-for-engineer`（及针对各角色的特化版本）完成：
- **只给 JS 编程面，不给裸 shell**：在沙箱内通过 `cat`、`stat`、`ls`、`rg`、`write`、`mkdir`、`rm`、`mv` 完成原子操作。
- **精准锚点**：使用 `where` / `whereAll` 精确匹配源码切片，严禁使用脆弱的手工 `indexOf` 或盲目正则擦除。
- **事务与快照保护**：读操作登记快照；写操作原子落盘前校验文件是否被并发修改。
- **挂起与恢复（park / unpark）**：遇到定位歧义或需要等待外部结果时，支持通过 park 挂起程序，由后续 unpark 恢复执行。

## 四、长程工作与上下文连续性

### 做成才是终点，不是单回合答复

- **做成原则**：使用者委托的是把事情彻底做成，而不是生成一段好看的回复。模型自然 stop、单次输出结束只是回合边界，只要任务未完成，就应当继续推进。
- **显式阻塞**：遇到真正需要用户或上层决断的事项时，必须明确交代清楚阻塞原因，不假装成功，不静默放弃。
- **Scope 机制（注解，无独立 reset 工具）**：
  - 每个工具调用带打平 `scope`（`resetScope`｜`keepLast`｜`removeLast`｜`meToo`）；额度是 retention（keep 容量），不是回合估计。
  - `scope.kind=resetScope` 结束当前闭环并立新目标／额度；宿主归档走 `ScopeReset.commit`。PairHint 以该注解（兼容旧工具名）为上下文屏障。
  - `removeLast` 出站把上一拍收成一条带教训的 assistant 消息；不物理改持久库。
  - 前缀稳定性（Prefix Stability）：历史前缀逐字节不变，确保模型生成的因果稳定。

## 五、模型调度与路由

- 系统不固定绑定单一模型，根据不同角色（Manager、Engineer、DevOps 等）的职责特征，由调度层（MJS scheduler）匹配最合适的模型。
- 配额与容量按实账管理，借出的容量及时归还，发生物理故障的 provider 及时隔离。

---

## 六、持久化与故障恢复

- **变故只以事件立身**：系统核心状态由追加式事件流（EventLog / Journal）折出，不采用直接覆写内存状态的做法。
- **重启与重放**：系统意外退出或进程崩溃后，通过重放不可篡改的事件流恢复现场。
- **单向依赖与三层演进**：
  - 底层事件抽象与状态机逐步迁入 `wanxiangli`；
  - 宿主信号（如 OpenCode 的 session-created、chat-message 等）收拢在 `wanxiangtong` 翻译层；
  - 本仓只负责组装与启动。
