# 委托惯例：验证前查总工头合入状态

写给 Manager / DevOps：在启动「构建 + 差分测试 + 提交推送」链之前，先确认总工头（或当前合入权人）**没有待合入的冲突提交**占着同一工作树。

## 谁查、查什么

- **谁**：发起验证的 Manager（或被明确委以验证链的 DevOps）。
- **证据**：`git status` 干净或仅含本委托预期改动；`git log origin/master..HEAD`（或对应主分支）无未说明的外来提交；若总工头有合入公告／horizon 回执，以之为准。
- **状态不明**：默认**等待**，不默认放行。代价不对称：误开验证会冲掉他人在途改动；多等一轮可挽回。

## 不做什么

- 不把「工作树看起来能编」当成合入许可。
- 不把本惯例写成又一道证明税门禁；它是协作礼貌，写进委托 charge 一句即可。
