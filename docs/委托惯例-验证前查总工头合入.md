# 委托惯例：验证前查合入状态

写给 Manager / DevOps：启动「构建 + 差分测试 + 提交推送」之前，先确认总工头（或当前合入权人）没有待合入的提交占着同一工作树。

## 谁查、查什么

- **谁**：发起验证的 Manager，或被明确委以验证链的 DevOps。
- **查**：`git status` 干净，或只有本委托预期的改动；`git log origin/master..HEAD` 里没有说不清的外来提交；总工头有合入公告或回执时，以它为准。
- **状态不明**：等着，不放行。误开验证会冲掉别人的在途改动，多等一轮可挽回。

## 不做什么

- 不把「工作树看起来能编」当成合入许可。
- 不把它写成又一道门禁；这是协作礼貌，在委托里写一句就够。
